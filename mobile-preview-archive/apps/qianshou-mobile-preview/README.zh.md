# 千手移动端网页版

[English](README.md) | 中文

网页版的窗口层就在本目录 `src/window/`：`startWindowEntry`、`MobileWorkspace`、`projectMobileWorkspace` 和 `materializeWindow`。DOM 绘制器是唯一的绘制操作，也是每个挂载必须注入的绘制器。这里复用仓库已有的 UI 分层，没有新增或宣称存在独立名为“UL”的包。

## 启动界面预览

在仓库根目录运行 `pnpm exec vite --config apps/qianshou-mobile-preview/vite.config.ts`，打开 `http://127.0.0.1:4175/`。这是仅监听本机的静态界面开发服务器，不是 Agent 应用启动入口。受支持的 Agent 运行时仍通过 `dsh` profile 启动。不需要安装新依赖或修改根配置。

账号代理默认指向 `https://qianshousuanli.com`。启动 Vite 前可用 `QIANSHOU_PREVIEW_ACCOUNT_ORIGIN` 指定 HTTPS 源或本机 HTTP 测试服务；页面“连接设置”会显示实际选择的源。代理保留账号 API 路径和 Bearer，移除请求中环境附带的 Cookie 与响应 Cookie。静态构建产物需要部署方提供账号代理，自身不包含后端。

AI 开发代理仅在原始 Origin 的主机与入站回环 Host 完全一致、且浏览器来源标记缺省或为同源时转换 Origin。外域或非法来源保持原样，生产 Host/Origin 校验继续生效。该规则覆盖整个 `/api/qianshou/ai/` 前缀，包括图片与订阅请求。

## 账号与会话

登录和 TOTP 使用 `createAccountClient`，随后通过 `/auth/me` 核实身份。凭据只留在内存，刷新页面需要重新登录。localStorage 只保存非秘密浏览器设备标识。电脑命令日志使用 `IndexedDbWindowJournalStore`；存储不可用时阻止启动。关闭页面会释放控制器和数据库；浏览器从往返缓存恢复已释放页面时重新加载。

侧边栏查询已验证账号名下的 Windows 和 Mac 节点。只有查询成功且没有在线电脑时显示“无远程主机”；未登录、未接入和查询失败分别显示。`createAccountPcDirectory` 检查电脑归属与心跳；电脑自行上报的 URL 不会直接授予会话访问权。

可信嵌入宿主可在入口加载前提供 `window.qianshouMobileHost`。其中 `agent` 类型端口必须连接账号所属的千手 Agent Session，使用现有规划、工具和循环；`authorizePc` 端口必须建立服务端授权的同账号电脑连接。这些端口必须在其权威服务核验账号归属；客户端传入的账号标识不等于身份认证。预览默认不提供两个端口。设置 `QIANSHOU_PREVIEW_AGENT_ORIGIN` 可启用独立移动 Agent HTTP 适配器；固定同源代理仅转发到配置的 HTTPS 或回环源，不嵌入平台密钥。接口必须由 `dsh-host-mobile-agent-gateway` 和账号私有运行时解析器装配；缺少部署配置仍显示不可用。有端口时只显示“已配置”，不宣称已验证健康。

共享控制器负责新建会话、历史选择、原文发送、按会话保留输入、发送中的重复点击保护和电脑接收回执。后台刷新时保留同一个 DOM 输入节点，避免打断输入法组字。本地创作建议与需求草稿只整理输入，语义理解和执行决定由 Agent 完成。页面没有裸 LLM 降级、虚假回复、手机算力贡献或自动付费生成。

## 原图识别

支持图片的 HTTP 端口声明 `supportsImageInput`，通过 `/api/qianshou/mobile-agent/v1/submit-images` 提交 PNG、JPEG、WebP 或 GIF 原始字节。共享工作区在现有串行准入链中捕获图片字节、保留原请求编号，拒绝向不支持图片的电脑或纯文字适配器发送。限制为最多四张、单张 8 MiB、合计 16 MiB；服务端负责完整图片解码校验。已确认的图片拒绝返回有界失败码；网络失败仍为状态不明，不自动重试。

浏览器辅助模块在既有修图路由前区分识图、OCR 与修图。只有附件而没有操作时简短澄清；普通文字不会自动附带最近图片。明确追问最近图片需要同账号、同会话、五分钟以内且不超过两个中间用户回合。编码保留原始字节，不通过画布缩小图片或抓取远端 URL；取消或切换绑定后丢弃迟到读取。页面接线与生产启用需要各自验收证据。

## 个人设置与语音输入

全页账号入口位于对话之后，登录区域纵向提供账号、手机号、微信和注册四项选择。手机号和微信服务尚未接通时保持明确禁用；账号登录、TOTP 和注册使用现有上海账号客户端。账号弹窗读取上海真实资料，只提交改动的显示名称、电话、国家地区和偏好语言，区分服务失败与空结果；用户名和邮箱只读。登录设备列表保留服务端状态和 IP，不允许撤销当前会话，撤销其他会话需要确认。密码和 TOTP 变更在上海确认所有会话需要重新认证后清除本地登录，迟到写响应不会清除后来切换的账号。页面不开放头像、通知偏好和可信设备管理。
全页账号入口位于对话之后，登录区域提供账号、手机号验证码、微信和注册入口。手机号验证码登录和注册使用上海短信接口；服务端确认发送后才显示脱敏手机号，登录遇到 TOTP 挑战先完成二次验证，再核验 `/auth/me`。微信登录的服务端换票尚未接通，继续显示不可用。账号弹窗读取上海真实资料，只提交改动的显示名称、电话、国家地区和偏好语言，区分服务失败与空结果；用户名和邮箱只读。登录设备列表保留服务端状态和 IP，不允许撤销当前会话，撤销其他会话需要确认。密码和 TOTP 变更在上海确认所有会话需要重新认证后清除本地登录，迟到写响应不会清除后来切换的账号。页面不开放头像、通知偏好和可信设备管理。

人民币充值页先读取上海支付通道状态，再开放支付宝或微信 Native。微信订单显示服务端下发的二维码，需另一台设备扫码；界面不宣称手机同机支付。页面只保存订单恢复标记，请求结果不明时不自动创建第二单，只有本人订单状态为 `paid` 才显示到账。

语音由用户主动开启。本机识别需要浏览器支持并已有语言包，页面不会下载语言或自动退回浏览器服务。使用浏览器语音服务前必须阅读告知并明确同意，随后才启动麦克风。真实语音控制器在识别结束后把终稿加入可编辑输入框；按住说话，松开后进入编辑，上滑可取消。自动发送是用户主动开启的偏好，默认关闭。切换账号或会话、页面进入后台、关闭页面或热更新销毁都会取消录音并拒绝迟到结果。麦克风效果和各平台权限仍需真机验收。

消息视图装饰共享 Session 投影，展示说话者、时间和用户主动触发的复制按钮，不将用户文字解释为 HTML。持续挂载的编辑器会随文字增高，在刷新中保留输入法组字，并继续使用共享发送去重及账号、Session 隔离。

## 界面功能映射

这是移动浏览器接入与交互预览，没有挂载完整的 `ui-slot-react` / `ui-renderer` 插件清单，不替代现有 PC 界面，也不代表整套 UI 插件迁移完成。共享移动窗口投影对话文字、接收回执和原始 Session 工具状态。登录后先恢复账号历史，确实没有会话才新建首条会话；运行中的 Agent 会话可以在原目标上取消。

| 功能界面 | 当前接入 |
| --- | --- |
| 登录、TOTP、账号电脑查询 | 共享账号客户端；生产用户登录仍需验收 |
| 移动会话、电脑目标、输入草稿 | 共享窗口移动控制器与窗口；真实 Agent 和授权电脑连接需要宿主提供 |
| 工具进度与取消 | 共享 Agent 事件投影与 Session 取消；完整工具卡片待后续实现 |
| 专员与子智能体树、交付文件与附件 | 尚未接入 |
| 文字消息、资料、登录设备、注册与语音输入 | 上海账号 API、共享 Session 投影、已提供时的 QianshouVoice 与经用户同意的浏览器语音识别 |
| 审批提示、交互问题与电脑画面流 | 尚未接入 |

## 验证与后续工作

运行 `pnpm exec vitest run apps/qianshou-mobile-preview/tests`，验证 DOM 交互、账号与 TOTP 身份准入、注册、真实空态与错误区分、Agent 原文提交、连续点击、稳定设备身份和真正 Vite 到本地 HTTP 的 Cookie 隔离。设置中的更新检查只读取官方版本元数据，不自动安装或重载；支付通道和订阅套餐从真实 API 读取，前端不编造价格，前往上海收银台的链接不在 URL 中携带令牌。隔离测试的 HTTP 和模型适配器不是生产服务；用户输出快照保存在本目录 browser-face 测试中。这些测试不证明生产登录、真实云端 Agent 执行、电脑中继授权或原生移动端安装。

运行 `pnpm exec tsc --noEmit -p apps/qianshou-mobile-preview/tsconfig.json` 与 `pnpm exec vite build --config apps/qianshou-mobile-preview/vite.config.ts --outDir /tmp/qianshou-mobile-preview-build`。当前源码依赖图中的 vendored Cordis、cosmokit 和 schemastery 存在既有严格类型诊断，范围比较会区分这些诊断与预览代码诊断。云会话历史现在来自服务端 Session 持久化；生产运行时供给、订阅模型凭据、授权电脑中继组装及部署仍是独立工作。
