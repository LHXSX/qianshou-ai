# 手机端账号、充值与订阅入口

`createAccountDialog` 保留原有工厂入口，`dialog` 参数接受 `HTMLElement`。应用可传入全页 `section`；`onOpen` / `onClose` 用于切换对话与账号页面的可见性。历史 `HTMLDialogElement` 调用仍兼容。`open()` 默认个人主页，历史 `open('profile')` 也进入主页；资料编辑由主页或设置的“个人资料”进入。设置、连接状态、充值、充值记录和订阅中心都是独立子页，页面内返回，不使用横排页签或底栏。

个人主页只呈现当前身份、服务端额度摘要和常用入口。登录方式保持账号、手机号、微信、注册四项纵排；账号密码和 TOTP 使用上海账号服务，手机号和微信尚未接通时明确提示，不伪造认证成功。注册成功返回登录。资料修改、密码、二次验证与登录设备撤销继续调用已有上海接口；账户切换、离开页面及销毁会取消读取并丢弃迟到结果。

设置中的“轻盈提示音”和“语音停顿后自动发送”使用应用共享的 `interactionPreference` / `setInteractionPreference`，默认提示音开启、自动发送关闭；不访问麦克风。`connections` 回调提供应用实际观察到的连接状态字段。组件不自行判断上海、广州或 PC 已连接。`account-pages.css` 仅作用于账号宿主，使用全页顶栏、有限内容宽度、纵向分组和清晰的身份层级。

## 充值

充值页使用当前账号 Bearer 读取同源代理下的上海 `GET /account-api/api/v8/payment/channels`；充值记录读取 `GET /account-api/api/v8/payment/orders?limit=30`，并核对每条订单的 `account_id`。通道配置失败不推定可用，未付款订单不展示为已到账。

“前往上海收银台”打开现有 `https://qianshousuanli.com/ea/#/wallet`，由已有模块完成充值；链接不带访问令牌，不新建第二套付款表单。用户需确认该窗口登录的是同一个账号。这个预览应用本身不调用上海 `/payment/recharge` 创建订单。上海账户余额与广州 AI 订阅余额分别展示；不承诺上海充值已自动转成广州 SP。

## 订阅

订阅中心读取 `POST /api/qianshou/ai/status` 的套餐、余额与 `prices.spPerYuanCost`。前端没有套餐价格或换算率默认值；缺少目录、金额、换算率或购买能力时不允许购买。进入套餐确认页本身不扣款；用户点击“确认余额支付”后，先重读目录核对报价和余额，再调用既有 `POST /api/qianshou/ai/subscription/purchase`，携带当前账号 Bearer，以及 `kind: subscribe`、`tier`、`months: 1` 和幂等键。不自动续费，不自动创建测试订单。

同一页面实例中，同账号、同档位的进行中请求合并；响应丢失后的重试复用原幂等键，允许服务端重放首次结果。无法取得有效订单回执时只显示“结果暂未确认”，不声称未扣费或开通成功。成功以后，订阅页面重新读取服务端状态，不在本地扣减余额。当前幂等凭据只保留在页面实例内，整页刷新会丢失；商用验收仍需验证持久恢复与订单查询。

## 本轮验证与未闭合项

账号与支付测试使用独立 HTTP fixture，不发出真实充值或订阅交易。覆盖独立页面导航、账号切换后的迟到结果、订单所有权、价格变化、缺失目录、二次确认、防双击与响应丢失后的同幂等键重试。服务端实际支付通道状态、真实到账和上海到广州余额衔接，以部署验收记录为准；前端测试通过不代表商业支付链已经全部闭合。
