# 千手供给管理

[English](README.md) | 中文

## 概述

打开**供给管理**，可以看清这台机器当前能否接单、服务端确认广告了哪些能力，以及这两件事背后的真实资源。所有事实都来自同一次已认证的观测，页面上显示观测时间。阻断原因逐条列出；服务端没有上报的事实一律显示为「未知」，不会变成 0、false 或空闲。策略编辑区提交的是完整策略，其中本页不编辑的本地价目设置会原样保留。这里不显示任何金额、收益、节点数或报价，因为收益结算数据源尚未接入。

<a id="use-this-package"></a>
## 使用本包

千手 web 组合通过常规客户端 bundle 挂载本包，把它放在与其他工作区相同的导航列表里。打开**供给管理**读取当前观测，然后选择参与方式、并发任务上限、空闲门槛和最低空闲内存。

### 页面回答的问题

四个问题，全部只依据实测数据。**准入**显示服务端状态（已关闭、暂不可接单、满足条件）并逐条说明阻断原因；本页尚未收录的原因代码会原样展示，不会隐藏。**广告**显示服务端是否确认过任何能力，并列出被确认的能力标识。**事实**显示操作系统、处理器、内存、GPU、探测错误，以及活跃度事实（空闲时长、前台任务、语音）；任何未上报的项都明确显示为「未知」。**策略**编辑主人设置，并说明这次保存真正存下了什么。

勾选能力是显式且可撤销的：只有自检通过的能力才能被勾选；策略中已启用、但本次观测未再发现的能力仍然可见并可取消勾选；服务端策略解析器不会接受的能力标识会阻断保存并指出该标识，而不是被静默丢弃。

### 最小配置

本包没有配置字段。在组合里把它作为普通的 `dsh.client` 行挂在拥有这些已认证路由的算力核心旁边即可：

| 字段 | 默认值 | 含义 |
|---|---|---|
| 无 | 必填 | 该行没有配置项；本工作区直接读取算力核心的路由。 |

## 理解实现

<details>
<summary>实现内部细节 — 点击展开</summary>

[控制器](src/client/controller.ts)负责两条已认证路由上的投影：一次刷新只做一次观测，同一时间只做一次策略提交，插件卸载时中止请求。观测失败时旧的快照只以「陈旧」保留：它带时间戳的事实仍可读，同时页面明确说明最近一次读取没有完成。[线格式层](src/client/wire.ts)重新校验每个字段，拒绝与自身状态定义矛盾的快照，并把 `null` 保持为未知而不代入任何值。[草稿](src/client/form.ts)镜像服务端解析器的规则，并始终提交完整策略，因此本页不编辑的价目设置会在保存后继续存在。[页面](src/client/SupplyPage.tsx)负责渲染事实和两个有限操作；[原因表](src/client/reasons.ts)拥有服务端代码的本地化解释。测试覆盖线格式合同、草稿规则、控制器竞态、页面渲染、插件席位与窄屏声明；另有一次真实 Chrome 实测，在手机、平板和桌面宽度下测量实际渲染结果。

</details>

<a id="model-experience"></a>
## 模型体验

### 机主已认证供给路由之上的浏览器工作区

#### 模型看到的内容

无：本包只提供一个浏览器界面，不注册任何提示词段落、工具、模式或会话事件。它读取 `GET /api/qianshou/compute/supply` 并写入 `POST /api/qianshou/compute/supply/policy`，两者都只针对机主自己的机器，页面渲染的内容不会进入模型请求。

#### Token 影响

无。本包没有任何请求组装路径会产生模型输入；同一桥上面向模型的工具属于算力核心的工具入口。

#### KV Cache 影响

无。本包既不组装也不发送模型请求，因此没有任何缓存前缀依赖它。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- 本页只渲染服务端上报的内容，自己不验证任何事实，也无法运行本机探测。
- 收益、节点数、平台报价和提速倍数是刻意缺席的：结算与派单数据源尚不存在，显示任何数字都等于捏造。
- 页面不提供接单或派发操作，因为真实任务链路仍在建设中，尚未验收。
- 策略中的价目设置只显示条数并被原样传回，本页不编辑任何金额。
