# 上海支付管理

[English](README.md) | 中文

广州管理台通过当前管理员的账号会话展示上海既有资金账本，不修改广州 SP 余额。`OrderView.vue` 将旧订单占位页接成全局支付订单、详情、手动充值和待处理提现队列。余额、状态迁移和平台管理员授权仍以上海为准。

## 入口与权限

既有 `/order` 页面和服务端菜单使用 `payment.read`。写操作需要独立的 `payment.manage`，全部支付路由要求数据范围为 `all`。凭据权限不会获得支付权限。内置超级管理员继承新增权限目录；既有财务、运营、客服角色不自动扩权。自定义角色按现有管理员流程授权。

代理只从服务端内存读取 `session.tokens.access`，转发至配置的账号 origin 与 `/api/v8` 前缀，不接受调用者提供的上游 URL 或 Bearer。请求不携带浏览器 Cookie、不跟随重定向、不自动重试。广州 RBAC 和上海管理员校验必须同时通过。

## HTTP 契约

下列管理台接口全部为 `/api/qianshou/ai/admin/payment` 下的 `POST` JSON。查询保留上海返回的十进制金额字符串与币种。浏览器不直接请求上海支付 API。

| 管理台后缀 | 请求体 | 上海请求 |
| --- | --- | --- |
| `/orders` | `limit`、`offset`，可选 `account_id`、`status`、`gateway` | 带分页筛选的 `GET /admin/payment/orders` |
| `/order` | `order_no` | `GET /admin/payment/orders/{order_no}` |
| `/withdrawals` | 空对象 | `GET /admin/payment/withdraw/pending?limit=200` |
| `/preflight` | 操作草稿 | 权威查询后签发既有确认令牌 |
| `/apply` | 相同草稿、`before`、`token`、`reason` | 确认和审计通过后向上海写一次 |

草稿支持 `confirm` 配合 `order_no`、`gateway_tx_id`；`recharge` 配合数字 `account_id` 和十进制字符串 `amount`；`approve` 或 `reject` 配合 `request_no`；`mark_paid` 配合 `request_no`、`paid_tx_id`。操作原因至少四个字，批准和拒绝会将原因传作上海的 `note`。

手工确认只允许待支付的 `admin_manual` 与 `bank_transfer` 订单。自动支付渠道由各自回调处理。提现批准要求 `pending`，登记已打款要求 `approved`，拒绝仅接受队列和上海服务允许的状态。登记已打款记录的是已经完成的转账；本管理台不会向银行发起资金转移。

队列最多含 200 条 `pending` 与 `approved` 记录，并非完整提现历史。收款信息从上海 `payee_info` 按字段白名单展示：账号由上海脱敏，户名和银行名可能保留；独立的 `payee_info_full` 对象不传入本台。上海当前契约没有按精确账号查询余额的接口，因此手动充值预览明确记为 `balance: null`，执行后的余额以上海成功响应为准。

登记已打款目前在两个确认阶段都由 `503 payment_withdrawal_gate` 门禁关闭。上海提现资金锁修复与独立审查完成前不能移除此门禁。查询和审批仍可使用；本地接线不能证明外部打款流程已经安全闭环。

## 确认与不确定结果

既有一次性令牌绑定操作者、草稿和权威改前状态。执行前重新查询目标，状态变化即拒绝。前端在两步之间冻结草稿，提交前消费本地预览，避免连点重复写入。重新创建确认属于操作者明确的新操作。

请求上海写操作前必须持久化意图审计，审计不可写即不提交。结果审计记录展示用改前状态、结果、操作者和原因，账号凭据与排除的完整收款对象不进入审计；允许展示的业务收款字段可能出现在改前状态中。上海成功但本地结果审计失败时，响应明确指出上海已成功并要求核查，不报告成普通失败。

上海既有手动充值接口每次请求都会创建新账本条目，没有调用方幂等键。因此网络错误、超时、5xx 或不完整写回执会返回 `payment_outcome_unknown`。再次确认前必须核查上海账本，代理不会重试。查询失败明确显示错误，不伪装空列表。授权拒绝、接口未部署或目标不存在、状态变化、服务不可用有各自错误码。

## 验证与交付边界

范围测试使用本地上海契约夹具，经过真实管理台 HTTP 链路和真实 Vue 订单页面，覆盖权限与范围分离、全局分页、服务端 Bearer 来源、收款脱敏、确认载荷不可变、并发点击、状态变化、十进制金额、审计失败与不确定结果。除两组测试外，还需后端 TypeScript 和前端 Vue TypeScript 检查。

新增全局订单和管理员详情路由与上海 T1/T2 本地候选对齐。旧生产契约只能列调用者本人的订单，绝不能替代全局列表。候选部署并通过授权联调前，全局查询可能明确报告接口不可用。本次本地开发没有修改生产数据库、凭据或执行真实支付。

微信、支付宝真实回调和商户凭据需要上海交付及真实验收证据。退款、删除账本、费率政策、SP 同步和打款政策不在本实现范围。模块就绪说明保留这些依赖，不宣称订单生态已经全部完成。
