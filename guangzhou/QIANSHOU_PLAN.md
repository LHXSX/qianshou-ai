# 千手智能体 · 开发计划

## 产品目标

把本机 DeepSeek Harness 改造成围绕真实项目工作的私人开发团队。用户通过文字或连续语音派任务，工作台显示子智能体、工具调用、文件、终端和实际结果。新任务默认并行派工，不等待正在运行的任务；补充指令仍可定向交给当前任务。

## 资源与技术选择

- 基线：DeepSeek Harness `c291e7961a515f6d7af9304e7fd1d257929aef26`，保留 Cordis 插件、会话日志、审批和模型接入。
- 界面：原有 React + TypeScript + CSS Modules + 类型化语言词典；语义主题统一管理深浅色。
- 语音：浏览器麦克风采集、语音活动检测、本地 whisper.cpp 中文转写、系统语音合成；语音投递共用文字输入的持久化和权限链。
- 团队：复用真实 subagent、fork、会话树和任务状态；新增直接派工 API，不等待主模型先生成工具调用。
- 开发规范：用户七步原文进入实际角色 persona，并保留在 [开发方法](DEVELOPMENT_METHOD.zh.md)；不能仅显示为说明卡片。
- 数据：会话、配置、凭证继续使用 Harness 的原有持久化方式。新版采用独立的本机数据目录，避免影响正在使用的原版。

## 调研依据与取舍

[Harness 官方仓库](https://github.com/deepseek-ai/deepseek-harness)已经提供文件、命令、会话和子智能体组成，继续扩展可以保留已有日志和授权链。重新写一个聊天后端会重复这些工作，并带来两套状态。

[Continue Agent Mode](https://docs.continue.dev/ide-extensions/agent/how-it-works)把模型工具、终端命令与权限交互放在同一工作流；千手沿用这种结果可追踪的交互原则。[OpenHands 并行执行](https://docs.openhands.dev/sdk/guides/parallel-tool-execution)展示了委派和独立执行的组织方式；千手需要进一步支持用户连续发送时直接创建子任务。

[Web Speech 的识别接口](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)兼容性有限，因此采用[whisper.cpp](https://github.com/ggml-org/whisper.cpp)作为本机语音识别引擎。该选择减少浏览器专用识别服务的依赖，代价是本机模型占用和逐段转写延迟。界面必须显示等待状态，不能把它宣传成已经达到原生实时语音模型的延迟与情绪表现。

## 模块与交付顺序

| 模块 | 交付内容 | 验收依据 |
| --- | --- | --- |
| 工作台 | 品牌、项目导航、对话、文件与工具结果、团队入口 | 真实浏览器操作与响应布局 |
| 开发规范 | 总设计师、产品架构、体验设计、工程、质量安全角色 | persona 内容与运行会话系统指令 |
| 并行派工 | 同会话连续分配子智能体、去重、任务归属 | 父任务不中断，两项子任务独立完成 |
| 连续语音 | 采集、转写、提交、执行、朗读、停止/打断 | 模块测试、本地中文音频与浏览器交互 |
| 安装与启动 | 独立数据、可重复启动入口、构建记录 | 冷启动、认证、真实模型请求 |
| 远程协作 | Windows/macOS/Linux 客户端、开发执行与远程桌面方案 | 独立设计文档；跨机连接需真实对端验收 |

## 质量要求

1. 模块依照现有类型化插件边界组合；不复制核心会话或审批引擎。
2. 子智能体必须有真实任务身份、父子关联和状态。发出派工与任务完成是不同的事实。
3. 停止语音或切换会话后，陈旧的转写请求不能再发送任务；朗读不回录为下一条指令。
4. 语音端点沿用认证与同源检查，限制音频格式、大小、时长和并发，临时音频在请求结束后删除。
5. 不虚构测试、远端设备、完成状态或所谓零错误保证；错误需要定位、修复并保留记录。
6. 远程桌面权限、远程命令权限、目录权限分别控制；不把本机开发服务直接裸露到公网。
