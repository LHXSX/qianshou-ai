# 千手产品层架构

[English](architecture.md) | 中文

本文描绘千手团队在 DeepSeek Harness 之上构建的那一层：用户看到的窗框、给它上色的设计令牌、承载产品功能的设置面、账户与订阅通路、管理控制台，以及打包链。它是一张有序的地图：每个机制点到名字并链接到它的归属处，而不在此复述。

## 外壳

产品窗口是由 `packages/client/ui-layout` 拥有的三栏框架。应用框架读取侧栏偏好、右栏偏好与视口宽度，再在 `packages/client/ui-layout/src/client/columns.ts` 里求解各栏宽度。求解器为中列保留最小值，当剩余空间容不下右栏最小值时把右栏收为零，并把侧栏夹在它自己的上下界之间。

三栏的职责互斥：侧栏承载导航与历史，主列承载当前工作，右栏承载这项工作的补充材料。不属于导航的内容型入口归设置，绝不进侧栏。

区域顺序不随视口宽度改变。团队状态在任何宽度下都留在会话右侧——它改变形态，不改变位置。

## 设计令牌

两套色板位于 `packages/client/ui-theme/src/qianshou-palettes.ts`。深色是近黑的中性底配金色点缀；浅色是白底配深蓝点缀。两套色板的面层令牌全部为中性色，因此强调色只出现在动作、选中、焦点与状态上。

令牌发布在 `document.body` 上的 `--dsw-alias-*`。浅色与深色的选择由设置里的外观行呈现，而每个预览色卡读的是同一批令牌，所以换色板不需要第二处定义。

维持配色纪律的规则、对比度下限与布局契约位于 `.agents/skills/qianshou-design-system`。其中的 `LAYOUT.md` 拥有对齐轴、区域内部排法、展开态规则与窄宽度阈值。

## 设置即产品面

`settings.section` 是产品功能的注册点。一个小节提供顺序、标签与注入的面，设置对话框把它们与上游小节一起渲染。

在那里注册的产品小节包括智能体广场、任务中心、工作流、应用市场、账号与套餐、文件与数据、模型与 API、协作设备与模型路由。侧栏的列表面只保留会话入口与账户入口。

同时需要按标识符可达的小节保留它的 `main` 注册，因为别处的代码会按 id 选中那些面板。

## 账户、套餐与用量

`packages/host/account-session` 拥有账户会话：它从服务解析账户、缓存已核验的身份，并判定一次失败是否权威。瞬时失败——网络、服务端错误、无法解析的载荷、限流、中断——在宽容窗口内保留上一次已核验的身份，而不是清掉它。

`packages/host/model-gateway` 拥有订阅网关。它发布平台可见的模型名、把它们路由到后端、在审计账本里记录逐次调用用量，并报告账号的档位与额度。档位及其模型可用性位于 `packages/host/model-gateway/src/tiers.ts`。

个人中心与套餐小节读同一个 store，因此两个面不可能互相矛盾。

## 管理控制台

网关暴露五条管理路由：已发布名目录、绑定追加、全站审计账本、订阅开通与订阅查询。授权是 fail-closed 的：部署未注入管理员声明时路由拒绝，而管理员集合是部署级配置而非默认值。

驱动它们的控制台是 `packages/client/ui-settings-routing` 里的模型路由小节。

## 模型路由与本机适配器

默认模型提供方由 `packages/llm/llm-deepseek` 提供。该插件声明一个提供方路由，并从它自己的配置读取端点；未配置端点时回落到 DeepSeek 的公开端点。因此，把产品指向本机订阅网关的部署必须显式提供该端点。

## 打包

`apps/qianshou-desktop` 拥有 macOS 外壳。两条路径产出应用包：`scripts/package-mac.ts` 构建可分发包，`scripts/install-mac.mjs` 从源码检出安装供本机使用。两者都必须写出名称、产品名与分发形态一致的壳清单，因为外壳从该清单解析它的入口。

应用内更新器位于 `apps/qianshou-updater`。它取回签名清单、用固定公钥与逐文件摘要校验归档、把新版本暂存在既有安装旁边，并在宿主退出后切换。归档认证不替代 Developer ID 签名与公证。
