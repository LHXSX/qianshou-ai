# 关键词触发与算力提醒卡 —— 设计

**设计约束（先读）**：卡片内容**必须匹配真实能力**，不能凭想象写。
`compute-core/README.zh.md` 明确声明：目录条目**不能证明**节点在线、价格有效、支出已授权或收益已结算；
且 H3/图像/视频插件**尚未接通**。所以本设计把"目录里有"与"现在能跑"**分成两个独立状态**，
卡片永远不同时暗示它们。

---

## 一、触发：三层匹配，且必须防误触发

### 1.1 关键词分两维（动作 × 对象）

| 动作词 | 对象词 |
|---|---|
| 生成、画、做、渲染、出、来个、帮我做个 | 视频、短视频、动画、图片、图、插画、海报、LOGO、封面、3D、模型、语音、配音、音乐 |

**触发条件 = 同一句里同时命中「动作词」与「对象词」**。只命中一边不触发——
否则"这个视频怎么优化"会被误判成生成请求。

### 1.2 必须排除的情形（否则会骚扰用户）

| 情形 | 判据 | 理由 |
|---|---|---|
| 疑问/咨询 | 句尾为 `？?`，或含"怎么/如何/为什么/能不能/支持吗" | 用户在问，不是在下单 |
| 否定 | 动作词前 3 字内有"不/别/无需/取消" | 「不要生成图片」不能弹生成卡 |
| 已有附件 | 输入区已有图片/视频附件 | 用户已在提供素材，多半不是要生成 |
| 已在生成中 | 该会话有进行中的算力任务 | 避免叠卡 |
| 历史已忽略 | 本会话内用户对同类卡点过"不再提示" | 一次打扰足够 |

### 1.3 一张卡原则

一次最多弹**一张**（取匹配度最高的）。多卡并列会把输入区变成菜单，违反布局契约 §2.2。

---

## 二、卡片内容：三段，且第三段随真实状态改变

```
┌─────────────────────────────────────────────────────┐
│  ① 识别                                              │
│     检测到你想生成视频                                │
│                                                      │
│  ② 能力与状态（两个独立状态，分开写）                  │
│     能力目录：图像 / 视频 ✅ 已列出                     │
│     本地执行：⏳ 尚未接入                              │
│                                                      │
│  ③ 动作（随状态改变，见 §2.1）                         │
│     [ 登记意向 ]  [ 改用轻量方式 ]  [ 不再提示 ]        │
└─────────────────────────────────────────────────────┘
```

### 2.1 三种状态与对应动作（**这是本设计的核心**）

| 状态 | 判据 | 卡片说法 | 按钮 |
|---|---|---|---|
| `available` | 目录有 **且** 本地执行插件已注册 | 「可以生成，预计消耗 X SP」 | **开始生成** |
| `catalog-only` | 目录有 **但** 无执行插件（**= 今天的真实状态**）| 「能力已列出，本地执行尚未接入」 | **登记意向**（不是"开始生成"）|
| `unknown` | 目录查不到该能力 | 「暂不支持该能力」 | 仅「收起」+ 建议替代 |

**为什么必须分这三种**：如果只有一种状态，`catalog-only` 时按钮写"开始生成"，
用户点了没结果——**那比不做这个卡更伤**。分状态之后，每一步都是诚实的。

### 2.2 成本必须标"来源与可信度"

`compute-api/README` 自己说报价**只读**且"不能证明价格有效"。所以成本行必须写清：

- 有报价时：「预计消耗 **X SP**（来自上游报价，最终以结算为准）」
- 无报价时：「**费用待定**——目录未提供有效报价」← 不许编一个数字

### 2.3 额度上下文（因为额度是账户级、多设备共享）

卡片上带一行账户额度：`账户剩余 389 SP · 普通版`。
理由：用户可能在手机上、也可能在电脑上，额度是**同一个**——不写清会让人以为各设备独立。

## 三、触发词表放哪：**云端下发**，不硬编码

理由（本次开发的直接教训）：端点配置写在本机时，为改一个值要改 profile、重启服务、
且**可能静默不生效**（今天为此耗掉好几轮）。触发词表同理会频繁调整，硬编码在客户端
意味着**每次改词都要发版**。

建议形态：随"运行时配置"一起下发（见需求书 `产品化需求-分发账户后台与算力.md` 的配置下发层），
客户端**本地缓存 + 离线可用**，云端不可达时用缓存，绝不因拉不到配置而阻断输入。

## 四、与既有机制的关系（不要重造）

| 已有 | 用途 | 与本卡的关系 |
|---|---|---|
| `conversation.input.overlay` 插槽 | 输入区上方浮层锚点（`InputBar.tsx:447`）| **卡片就挂这里**——天然是浮层，符合布局契约 §2.2 |
| `ui-input-trigger`（`trigger: '/'` `'@'`）| **符号型**触发菜单 | **不复用**：它的契约是 `sources(trigger)` 按符号索引，关键词不是符号，语义不匹配 |
| `GenericCommandCard` / `ApprovalCommand` | 卡片渲染底座 | 可参考形态，但本卡需要独立的三段结构 |
| `compute_capabilities` 工具 | 查算力目录 | **卡片的数据来源**（判断 `available` / `catalog-only` / `unknown`）|
| `compute_plan_draft` 工具 | 存本地草稿 | 「登记意向」落到它 |

**结论：新建一个独立模块，订阅草稿变化 → 匹配关键词 → 查目录 → 往 `conversation.input.overlay` 注册卡片。**
不改上游契约、不碰符号触发器。

## 五、验收标准

1. 「帮我生成一个视频」→ 弹卡，状态 `catalog-only`，按钮为**登记意向**
2. 「这个视频怎么优化」→ **不弹**（疑问句）
3. 「不要生成图片」→ **不弹**（否定）
4. 「生成图片」连说两次 → 第二次**不再弹**（同会话已提示）
5. 卡片弹出一瞬间，**输入区控制行高度不变**（布局契约 §2.1；用 `input.overlay` 浮层即天然满足）
6. 目录不可达时 → 卡片显示 `unknown` 并说明"无法查询能力目录"，**不猜**
7. 关键词表改动**不需要发版**（从云端配置读取）

## 六、分期

| 期 | 内容 | 依赖 |
|---|---|---|
| **一** | 关键词匹配 + 卡片 + 三种状态（`catalog-only` 为今天的真实态）+ 登记意向 | 无后端依赖，**可现在做** |
| **二** | 接通派发后，`available` 态点亮「开始生成」+ 真实报价 | 算力派发接通 |
| **三** | 卡片内联进度与结果预览 | 结果回传接通 |

**第一期不依赖任何未接通的后端**，且每一步都诚实——这是它值得先做的原因。
