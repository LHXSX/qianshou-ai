# 千手智能体 desktop shell

English | [中文](README.zh.md)

This private local shell loads the compiled Harness web profile in a sandboxed Electron window. It owns a separate backend process, home, browser session and single-instance lock. It does not replace the official Harness desktop or attach to an existing server.

Build the repository's host libraries, CLI and branded web client first. With Electron downloaded under `apps/desktop/node_modules/electron`, run `node apps/qianshou-desktop/scripts/install-mac.mjs`. The installer creates `~/Applications/千手智能体.app`, signs it locally, preserves an existing application as a timestamped backup, and writes a private installation receipt. This command remains the developer launcher using a stable source checkout and configured Node executable. Public preview builds use the separate portable packager below.

Host compilation and bundling are separate requirements: `lib/types` alone cannot satisfy a Loader import of `lib/index.js` or an exported subpath. Rebuild affected Host packages after adding profile plugins or package exports, then validate the installed shell's web profile before launch; see the [Loader-entry build record](../../.agents/notes/implemented/bug-fix/2026-09-13-qianshou-loader-entry-builds.md).

Defaults are source `~/.local/share/qianshou-agent/source`, Harness home `~/.local/share/qianshou-agent/home`, and `127.0.0.1:3081`. Override paths and port in `~/.local/share/qianshou-agent/desktop/config.json` or `QIANSHOU_SOURCE`, `QIANSHOU_NODE`, `QIANSHOU_HOME`, `QIANSHOU_PORT`. Installation records the terminal's PATH for Finder launches; override it with the config's `path` or `QIANSHOU_PATH`. The default web profile is used. Port 3080 and public bind addresses are rejected. Quitting stops only the backend started by this shell: its process group on POSIX, or its PID-owned process tree on Windows. An occupied port causes an error instead of takeover.

Authentication URLs are consumed in memory from the web profile's readiness line. Logs under `home/desktop-logs` redact URL tokens and request mode 0600 on POSIX; Windows access depends on the directory's account permissions. Only the trusted main page can request audio capture. The preload exposes `window.qianshouDesktop.openRustDesk(id)` and no arbitrary command or filesystem API. This method accepts 6–12 numeric digits, launches an installed RustDesk executable with `--connect`, and returns `{ok:true}` on process spawn or `{ok:false,error}`. Launch success does not prove remote connection or authorization. `QIANSHOU_RUSTDESK` can name an absolute executable path.

The ESM entry completes evaluation before waiting for Electron readiness. Run `node --test apps/qianshou-desktop/tests/*.test.mjs` for real child-process ownership, cancellation, port isolation, token redaction, navigation and microphone policy checks. The Windows controller has a separate portable preview described below; a Linux controller package is not provided.

The current Mac delivery has completed installation and an initial workbench window launch; see the [local delivery verification record](../../QIANSHOU_VERIFICATION.md) for dated evidence and remaining checks. System microphone permission, live microphone and speaker behavior, and an actual remote desktop session still require on-device acceptance. Process and automated browser tests do not establish those results.

The trusted preload also exposes the optional relay capability for native registration import, explicit enable/disable and credential-free status. Each launch begins with relay disabled. Setup and security details belong to the [relay guide](relay/README.md).

## Portable preview

Product version 0.2.1 is distinct from the underlying Harness engine version. Prepare the verified upstream Node/pnpm runtime with `node apps/desktop/scripts/prepare-runtime.ts`. After the complete Host build, point `QIANSHOU_WEB_DIST` at a clean branded web build and run `node apps/qianshou-desktop/scripts/package-mac.ts`. `QIANSHOU_RELEASE_OUTPUT` selects a fresh output directory; existing artifacts are never overwritten. The packager reads the installed dependency graph without running an installer or modifying workspace package-manager state, retains package licenses, copies declared workspace runtime files, and creates only internal relative dependency links. Unique first-party plugins are also visible at the runtime root for Cordis dynamic profile imports.

Both controller packagers stage the public relay modules, Apache-licensed FRPC and explicit ISRG certificate roots from the [relay lock](relay/frpc.lock.json). The archive, executable, license and CA hashes are checked for the requested platform; a source Mac executable is never reused for Windows. `QIANSHOU_FRPC_CACHE` may name a directory containing the locked official archives. Enrollment tokens, tests and generated source manifests are excluded; each package receives a fresh target manifest. See the [dedicated relay service](../qianshou-relay/README.md) for authentication and operational limits.

The macOS arm64 preview contains Electron, Node, pnpm and the full web profile. Packaged launch resolves immutable resources relative to the moved application, ignores legacy source/Node overrides, preserves the user home, and prepends bundled tools to PATH. Help menus open the bundled quick start and optional local-voice instructions. Voice resources use the installer-owned path manifest; existing environment and explicit Host settings remain authoritative. Preview signing is ad-hoc only and is not Apple notarization. A fresh-home authenticated launch, frontend load and owned shutdown must pass before publication; unit tests or `--version` alone do not establish runtime closure. See the bundled `QUICK_START.md` / `QUICK_START.zh.md` and the [packaging note](../../.agents/notes/implemented/feature/2026-09-13-qianshou-portable-preview.md).

## Windows x64 preview

The unsigned Windows controller targets Windows 10/11 x64 according to the [Electron 44.0.0 platform requirements](https://github.com/electron/electron/blob/v44.0.0/README.md#platform-support). The ZIP opens through `QianshouAgent.exe` and contains a Windows Node executable and target-specific native dependencies. Windows device launch and end-to-end acceptance remain unverified; the release retains `verified: false`. User installation and manual checks belong to the [Windows quick start](QUICK_START.windows.md).

The Windows packager consumes the prepared `win-x64` runtime, checksum-verified Electron archive, clean branded web build and verified target-native package overrides. From the repository root, run `QIANSHOU_WEB_DIST=<clean-web-directory> QIANSHOU_WINDOWS_NATIVE_OVERRIDES=<overrides.json> QIANSHOU_RELEASE_OUTPUT=<fresh-output-directory> node apps/qianshou-desktop/scripts/package-windows.ts` in a POSIX build shell; `package:windows` is the package-local script for the same entry. The release packager owns this operation and records archive, native-file and dependency-resolution evidence separately from target-system acceptance. Existing output directories are rejected.

Packaged Windows startup resolves `resources/runtime/node/node.exe`, merges inherited `Path`/`PATH` into one child environment entry, and preserves `%USERPROFILE%\.local\share\qianshou-agent\home` unless a home override is configured. The controller uses the existing [PowerShell provider](../../packages/shell/pwsh-local/README.md), not a new CMD-only executor. Shutdown waits for the PID-scoped `taskkill /T /F` helper and backend exit; failure or timeout is reported and logged instead of treated as confirmed cleanup.

The packager maps the Windows-specific quick starts and voice guides to ordinary bundled names and rewrites their paired links. It includes no Mac voice installer. System TTS depends on available Windows voices; dictation and continuous voice need separately configured recognition resources. See the [Windows voice guide](voice/README.windows.md) and the [Windows controller decision](../../.agents/notes/implemented/feature/2026-09-13-qianshou-windows-controller.md) for platform limitations and verification ownership.
