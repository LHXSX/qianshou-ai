# 通过协作中转连接

[English](README.md) | 中文

## 概要

中转让协作端通过专属 HTTPS 地址连接正在运行的桌面主控。它承载既有设备连接；配对码、允许的工作区和本地任务批准仍然有效。每次启动 App 时中转都关闭，原有直连主控地址仍可使用。

<a id="enable-and-share"></a>
## 启用与分享

使用支持中转的 0.2.1 或更新桌面主控，并向中转管理员取得专属注册 JSON。浏览器和较早的桌面外壳无法启动此连接。公开安装包不包含注册令牌。

1. 打开**协作设备 → 公网协作中转 → 导入专属配置**，在原生文件对话框中选择原始 JSON。App 校验后通过操作系统凭据服务保存加密副本。
2. 点击**启用中转**，等待**中转已连通**。这表示 FRPC 报告预期设备路由正在运行；仅显示**正在连接**不能证明注册或远端可达。
3. 点击**复制中转地址**，或在下方接入说明中点击**使用已连通的中转地址**。生成新的一次性配对码并复制完整接入说明，把地址、配对码和公开协作端下载说明发给对方；专属注册 JSON 应保密。
4. 对方安装协作端，输入地址和配对码，选择允许的工作区。确认设备上线后发送一次查看目录任务，由对方批准并检查结果。

主控需要保持打开并联网。每个设备任务仍需对方批准。远程桌面另外使用 RustDesk 及其本地权限；此中转不承载通用桌面或任意 TCP 隧道。

<a id="stop-or-recover"></a>
## 停止或恢复

**关闭中转**会关闭这条中转连接并断开经它连接的设备，不会停止无关的本机智能体任务或主控后端。正在进行的协作端任务可能因设备连接断开而中断。关闭 App 会停止其自己启动的 FRPC 进程并删除临时明文配置；每次重新打开 App 都需手动启用。

如果一直显示连接中，请检查网络和管理员提供的注册信息，再关闭后重新启用。运行资源缺失或校验不符时，请使用完整的当前安装包。系统凭据加密不可用会阻止导入，不会改用明文保存。已保存注册信息无法解密时，请重新导入原始 JSON。更换注册信息前需要先关闭中转。关闭错误表示无法确认清理完成，会明确显示。

原有直连邀请独立保留。输入的 HTTPS 地址只检查格式；在协作端实际连接前，不保证它可达。配对码仍然五分钟有效且只能使用一次。

<a id="security-and-verification"></a>
## 安全与验证

桌面渲染进程只看到公开地址、启用和配置标记、连接阶段及有限错误码。只有受信主页面的 IPC 调用能打开原生导入对话框；渲染进程不能选择文件路径、可执行文件或转发目标。加密注册信息位于桌面用户数据的 `relay` 目录。FRPC 只在启用期间读取私有临时配置。注册令牌不会打包、进入邀请文本或写入日志。

启动前按目标资源清单校验固定 FRPC 可执行文件和 ISRG 根证书的 SHA-256，必须验证 TLS 对端。本机网关只绑定回环地址，仅向当前 App 所属后端转发路径严格为 `/qianshou-device` 的原生 `GET` WebSocket 升级请求，拒绝浏览器 Origin、其他路径和普通 HTTP。认证后的 FRPC 状态接口只绑定另一个回环端口，不会通过中转公开。

开发检查使用 `node --test apps/qianshou-desktop/relay/tests/relay.test.mjs` 及现有桌面入口测试。可选 `tests/public.test.mjs` 使用 `node --import tsx/esm --test` 运行，接收管理员提供的 `QIANSHOU_RELAY_ENROLLMENT` 文件路径及可选 `QIANSHOU_RELAY_RECEIPT` 回执路径。它创建独立主控和协作端，验证实际公网 TLS、本地批准、文件结果与关闭清理。测试中的 AES 实现证明加密持久化行为，不代表已验收 Electron 系统凭据库或 Windows 真机。参见[中转决策](../../../.agents/notes/implemented/feature/2026-09-14-qianshou-dedicated-relay.zh.md)。
