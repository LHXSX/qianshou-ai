# 千手出图模组：三种供给来源与视频首帧

[English](qianshou-image-module.md) | 中文

用户始终从 `@出图` 输入自然语言，选择图像后在会话中预览、修改和保存。模型、节点与 API 是供给来源，不是三套买家界面。普通人只需说画面内容，按需回答用途、画幅、风格、是否参考已有图片；专业创作可展开构图、角色一致性、参考图、种子与批量变体，但只能使用所选已审核配方允许的参数。出图订单与 `@出视频` 订单各自报价和授权，图片可经用户确认后成为视频首帧或视频圣经中的角色、场景锚定资产。

## 三种来源

1. **本机模型。** 用户在自己的 PC 安装并验收已审核的出图配方，用本机资源出图；这一步不等于把设备开放给陌生人的订单。通义的 [Z-Image 模型家族](https://github.com/Tongyi-MAI/Z-Image)是首批候选，其中 Z-Image 与 Z-Image-Turbo 是不同配方；最终支持的模型版本、运行环境、文件摘要、显存要求、尺寸范围、推理参数和许可要以平台清单与本机实测为准。模型不存在时说明下载大小、来源、许可和空间需求，由机主确认后安装并验机。不能把 H3 视频模型当成所有图片任务的必需依赖。
2. **生态节点接单。** 机主在本机出图真实通过后，可另行发布图片能力并开启接单授权。上海按已审核发布编号、配方版本、设备能力、队列、价格、隐私范围和成功率分配订单；节点生成图片并传给广州核验、存储和交付。该节点可以运行 Z-Image 或其他受审配方，不要求每台机器安装同一种模型。机主能看清“可自用、可发布、审核中、可接单、暂停接单、订单、收入”的区别。
3. **第三方云端 API。** 经平台单独审核的提供方接入相同的出图任务与结果格式。提供方的输入、数据去向、可用性、尺寸、价格、使用许可、超时与失败回执必须明确；不把用户素材送往未经授权的 API。该来源的费用与节点报价分别展示，用户确认价格后才能调用。第三方不可用时重新报价并让用户确认替代来源，不能悄悄换模型或加价。

三种来源共享 `image.generate` 的买家语义，具体发布可分别声明文生图、图生图或编辑能力；不会因为名称相同就把编辑参数发给只支持文生图的配方。发布清单要绑定能力版本、模型或服务版本、工作流摘要、输入约束、输出格式、尺寸与价格；本机和生态节点可复用同一执行器，但自用、市场授权和收费是不同状态。云端 API 用独立提供方适配器，不冒充本地设备。

## 对话、报价与图片资产

对话先整理用户原话；缺关键信息时一次只问一件事，可跳过非必要问题。先展示“要画什么、画幅、风格、参考素材、预计几张、可选来源”，再取得该发布版本的真实报价。用户确认创意不等于同意付费；报价变化、来源切换、修改图片数量或尺寸都要重新询价和确认。排队时展示当前订单可核验的阶段：等本机资源或兼容节点、运行中、上传核验中、可预览、失败或暂停；没有可靠队列位次和 ETA 时不显示猜测的数字。

每张交付图片保存生成订单、发布与配方摘要、来源、内容 SHA、MIME、宽高、授权范围、广州对象桶/key/版本和核验结果。用户从会话里挑选真实生成图作为视频首帧时，客户端展示预览并获得使用确认；视频订单再绑定那张图片的精确对象版本与摘要，并按视频配方要求检查画幅、格式和大小。出图费用与视频费用分别列示；修改或重新生成首帧会使旧视频报价失效。上海只保存订单与调度元数据，不中转图片字节。

长片先锁定角色、场景和风格参考图的版本，再按章节与镜头派给兼容节点。图片资产被替换时只重排真正依赖它的镜头，并提示预算与进度变化。视频圣经的每个镜头仅能读取获授权的图片版本，不能靠相似文件名猜测素材。

## 当前源码与验收范围

当前 `image.generate` 的能力词汇已存在，但市场可接单、云端提供方、Z-Image 安装验机与生成图转视频首帧尚未贯通。`commerce-image-workflow` v2 只预览节点路线，由调用方传入图片配方所需模型 ID；它不核实配方是否已审核，也不授权执行。旧 v1 的 H3 加占位模型硬编码已移除，尚无 v1 持久化订单或运行时消费者需要迁移。现有视频首帧流程只使用用户选中的真实本地 PNG/JPEG；本机 Comfy 私有试用出图也不是市场订单。上线前须分别完成三种来源的真实出图、报价和授权验收，以及生成图作为首帧的跨任务资产验收。未通过前不显示“自动帮我生成首帧”可用，也不把纯色测试图或图片路径当成成品。
