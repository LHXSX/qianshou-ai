# 千手视频模组：普通用户出片与异构节点接单

[English](qianshou-video-module.md) | 中文

视频应是一个独立的产品模组，而不是为每台电脑、每个技能开一条通道。对买家显示统一的 `@出视频`；后台使用版本化的 `video.render` 任务合同选择已审核的具体工作流、节点和价格。节点可有不同操作系统、模型和设备；H3/5080 只是首批验收样机。每次订单必须锁定一个发布编号、合同摘要和资源上限。上海只处理审核、报价、订单和调度元数据；首帧和 MP4 字节经广州对象存储与执行节点传输。

第一次使用 PC 的人应能直接登录、对话和完成基础任务；需要视频、设计或其他专业能力时，再由能力模组解释能做什么、所需素材、预计价格和结果形式。节点机主看到的是“本机能提供哪些能力、还缺什么、是否可以接单、订单与收入”，不需要先理解 JSON、ComfyUI 图或服务器拓扑。高级配置可以展开，但不能成为普通用户开始使用或机主看懂状态的前提。

## 买家：普通人三步，高手按需展开

1. **说想法。** 输入一句自然语言，例如“做一段小白猫从草地跑向镜头的 5 秒短片”。解析成可回看的目标描述，不暗示 AI 已理解画面内容。
2. **补最少的信息。** 只追问缺少且会改变结果的事项：主角和动作、用途或画幅、首帧来源。若已在原话中说明就不重复问。时长、画幅、声音等默认值只有在当前已审核合同明确支持时才能预填；不支持就显示可选范围。最多一屏完成，非必需细节可跳过。
3. **确认后执行。** 显示最终描述、选中的真实首帧及其来源、预计时长/画幅、单次人民币报价和预估等待。创意确认仅允许上传被选中的图片快照；真正扣费须另行确认服务端报价。任务完成后在会话里给可播放 MP4 文件卡、下载和失败原因，不只给磁盘路径。

首帧入口分为“用我的图”“从这台电脑找图”“帮我生成图”。前两项只显示真实可读的本地图和缩略图；第三项必须有独立可用的生图提供方和单独报价，不能用假图充数。没有首帧但当前合同允许文生视频时可以跳过；当前 H3 工作流若要求首帧，就明确提示并禁止下单。确认前浏览、问答和选择图片不上传任何媒体。

“高手模式”收在同一模组的展开区：镜头运动、构图、风格、负面约束、种子、首尾帧或分镜，只显示当前审核合同声明的字段、范围与费用变化。额外自然语言可整理成描述，但不能变成任意 Comfy JSON、任意本地路径或未审核参数。普通模式与高手模式最终都产出同一种订单合同。

## 节点：安装、验机、审核、接单是四个不同状态

节点第一次开启某项视频供给时，按该能力的已审核清单做只读预检：硬件余量、驱动、执行服务、模型与插件角色、工作流摘要、编码器、输出空间、当前账号和设备绑定。H3 配方才要求 ComfyUI、H3 五个模型角色和固定四步工作流；其他配方按自己的合同核验。每一项显示“已就绪 / 缺少 / 版本不符 / 无法确认”；无法确认按缺少处理，不靠文件名猜测模型可用。

缺少组件时给用户明确安装包大小、来源、授权和预期磁盘空间，**由机主确认下载**；下载只接受平台审核的版本清单与内容摘要，支持中断续传和完整哈希核验。模型和工作流放在节点私有目录，不能把买家素材、模型文件或绝对路径传给上海。已有组件通过核验即可复用；未来不同显卡与模型使用不同的审核配方，不要求每台 Windows 都重新改代码。

安装完成只得到“本机可试用”。随后用两次独立 5 秒样片确认：同一锁定图、真实模型/插件、实际 GPU、唯一 MP4、完整帧解码及产物 SHA。通过后可创建本地技能草稿；发布仍要平台审核版本、来源、报价和独立结果验收；最后机主单独启用接单授权。任何更新、模型替换或工作流摘要变化使旧验机失效，重新预检与审核，不沿用旧绿色状态。

## 每单不可省略的绑定

- 买家从实时目录选中一个可用的审核发布版本；`@出视频` 若有多个不同合同，应先让买家选择，不能静默切换。
- 询价和创建任务都绑定发布编号、产物摘要、合同摘要、首帧对象的桶/key/版本/SHA/大小/MIME、描述与参数。下单前重读审核状态和实际报价，变更则重新确认。
- Windows 在占用 GPU 前和提交 Comfy `/prompt` 前，复核签名订单、设备安装、当前审核、版本化首帧字节与一次性持久预约。未知 `/prompt` 结果不重试。只接受本次 attempt 前缀的唯一 MP4。
- Windows 上传 MP4 至锁定的对象版本；广州独立读取并完整解码、核对当前订单与对象锁后签结果回执。上海不下载视频、不代做媒体验收。Mac 以广州授权的媒体地址展示可播放交付。

## 验收口径

“可发布”至少需要：公开视频合同真实注册且审核通过、Windows 在真实 NTFS 上证明一次性账本、版本化素材下载、超过现有小文件上限的流式 MP4 上传、广州 HTTP 验收与签名回执、一次真实的买家确认报价→上海派单→Windows GPU→广州验片→Mac 播放闭环。源码编译、本机样片、目录卡片或单元测试都不能单独称为市场可接单。

当前源码已有买家自然语言/本机首帧推荐和审核版本绑定候选、Windows 默认关闭的 Comfy 执行消费者候选、上海隔离源码补丁及广州独立验片候选；上述真实跨机闭环仍未验收。旧固定 H3 样片只是验机证据，不能替代通用视频模组的订单结果。

## 三种出片策略共用一个视频项目

用户始终从 `@出视频` 进入。**轻松出片**与**专业创作**都通过对话补全需求，不把 JSON、节点图或设备配置放在买家面前。轻松出片只追问会改变作品的缺项；专业创作逐步讨论剧情、场景、角色、分镜、镜头、声音、首帧和时长，并允许修改方案。AI 可草拟方案，用户确认创意后再看项目报价；一次项目报价必须覆盖计划中的生成、独立出图、合成与验收，额外费用须再次确认。用户选择以下执行策略，系统也可按已审核供给推荐，但不得静默改变价格、模型或最终时长。

1. **1 对 1 短片。** 一个已审核视频配方在一台符合条件的节点上完成一个镜头；当前 H3 五秒图只是此模式的一种配方。明确告诉用户该配方支持的实际时长、画幅、首帧要求与声音能力。用户说“一分钟”而只有五秒合同可用时，先转入长片规划，不能拿五秒合同报价。
2. **1 对 1 长片。** 一个视频项目先生成剧本和分镜，再拆为多个有编号、可单独核验与恢复的镜头任务；所有镜头优先由同一台兼容节点顺序执行，最后做音频、字幕、转场和成片合成。十分钟不能包装成一次不可恢复的 GPU 调用。设备离线时项目暂停；若允许迁移，须重新核验另一台节点的配方兼容性、资产授权、价格和质量边界。
3. **1 对 N 分布式长片。** 同一份已确认的项目计划拆成依赖图；上海只按能力版本、可用槽位、显存、队列、时限与报价分配任务元数据及短租约。可并行的独立镜头分给多个兼容节点；依赖上一镜头尾帧、同一人物锚定或连续场景的镜头按依赖顺序运行或作为连续镜头组派发。不能按总时长平均切给 N 台，也不能把不同模型输出假定为风格一致。需要跨模型制作时，先通过参考图与样片核验，达不到连续性要求就提示换配方或收敛到兼容节点组。

分布式的收益应向用户说明清楚，但不承诺线性提速。一小时最终时长若以五秒镜头粗算约 720 段；100 台**实际在线且同配方兼容**的机器、镜头完全独立、每台同时只跑一段时，纯生成的理想下界约为 8 轮。真实调度应以各镜头耗时预测、场景依赖、显存/队列和节点成功率计算关键路径与可用并发，另计剧本、锚定图、上传、逐镜验收、返工和最终合成。界面显示真实可用节点数、可并行镜头数与估时依据；没有可靠测量时只显示阶段，不给虚假的“100 倍加速”或确定完成时间。

三种策略共享 `视频项目 → 镜头计划 → 受审配方/资产 → 节点尝试 → 单镜头验收 → 合成验收 → 成片交付` 的身份链。由上海保存项目、订单、镜头依赖、任务/租约、预算与终态元数据；剧本、参考图、首尾帧、镜头视频和成片字节存放在广州授权的版本化对象存储或执行节点，不经上海中转。规划模型和[出图模组](qianshou-image-module.zh.md)是独立的受审能力，可由节点执行；不能因为 H3 能生成某种图，就把尚未发布和报价的出图服务当成已可用。

一小时作品需在镜头之上增加**章节/场景**层级：先用对话确定观众、题材、人物、章节数、每章目标时长与预算，再产出完整剧本、人物关系和视频圣经；用户逐章看剧情梗概与分镜，选“交给系统安排”或指定某位创作者/某台已认证设备负责该章。指定设备仍必须满足该章配方、负载、授权和时限；不符合时给可理解的原因和替代方案，不偷偷改派。每章先做少量关键镜头或低成本样片，通过角色与风格连续性检查后才批量运行该章；章节之间可并行，但共享人物资产变更会让依赖它的章节重新确认。项目可分章给粗剪与修改意见，最终由统一的合成任务处理对白、配乐、字幕、章节衔接、片头片尾和整片验收。

## 视频圣经与可恢复的镜头计划

“视频圣经”不是一张万能参考图。它是经用户确认的版本化项目包：角色面容与服装、场景和道具、画风与色彩、关键参考图、镜头语言、音色/对白规则、允许的模型与工作流版本、素材授权，以及明确的禁用内容。每个镜头只领取自己获授权使用的资产版本、提示词、时长范围、输入输出合同和上游镜头回执；节点不可自行改写圣经或取整个项目的无关素材。圣经或分镜一旦修改，受影响镜头的报价与旧产物状态应失效，未受影响且仍兼容的已验收镜头可以复用。

一个“1 分钟”请求是最终成片时长目标，不等于某模型能单次连续生成 60 秒。规划器先依据已审核配方的真实时长、镜头复杂度和前后依赖提出镜头数与每镜目标；再由用户确认故事、时长误差范围、预算上限和执行策略。譬如五秒配方可能需要约十二个镜头，再加片头、转场或剪辑；实际镜头数由剧情和合同决定，不能固定除以五。十分钟同理，但项目预算、队列与中途修改成本会更高。

单镜头失败只处理该镜头及受其依赖的后续镜头。已提交但回执不明的 GPU 作业不得自动重发；先核对原尝试、对象版本和费用，再决定显式恢复。节点替换也只能发生在新尝试，不能让两台机器对同一尝试同时提交结果。广州对每个镜头以及最终 MP4 分别核来源、锁定版本、摘要和完整解码；最终合成可作为独立受审计算任务在节点执行，上海只接收核验回执。

## 对话、排队与费用的可见性

对话中的方案确认卡应显示“要拍什么、预计几段镜头、需不需要用户素材/平台出图、目标时长、可选执行策略、预算范围”。用户回复“可以”只确认方案；先完成所需素材与单次真实报价，再由用户确认最高金额，后台才可自动排队与运行。专业创作允许在报价前逐段修改剧情和分镜；报价后修改要重算影响范围并重新确认，不能沿旧授权继续扣费。

会话内持续显示项目阶段与可操作的下一步：规划、待确认、等素材、已报价、等待兼容设备、生成第几个镜头、逐镜验收、合成、成片验收、可播放交付，或暂停/失败/取消。只展示服务端真实的本项目队列位次、镜头完成数、进度与预计时间；当前回执没有位次或 ETA 时明确显示“暂无法估计”，断线时保留已确认的历史而把实时百分比标为待核查。长片允许用户看已验收镜头、知道下一段在等什么、取消未启动部分，并看已完成费用与可退余额。最终产物在对话内可预览和下载，不只给本机路径。

正式验收须分别证明：短片单节点、长片单节点中断恢复、长片多节点依赖/并发/失败隔离；不同设备和已审核配方的准入；独立出图的报价与资产授权；项目级预算上限、部分取消与结算；真实队列/进度回执；所有镜头及最终成片可播放。现有 H3 固定配方、单镜短片向导和基础任务进度不足以宣称三种策略已上线。

目前客户端审核输入合同仍是“一个真实首帧 + 一段提示词 + 一个 MP4”的单镜任务，旧固定 H3 发布配方只有五秒。通用 Comfy 合同解析器容许声明单镜最长 120 秒，那是**格式上界**，不是当前已审设备能生成一分钟的证明。独立平台出图、项目/章节/镜头订单、逐镜队列回执、自动合成和一小时项目预算授权尚未接入。新版对话可以先讨论长片方案，但在这些合同和供给真实通过前不得把长片方案转换成五秒任务收费。
