# Fixed-workflow local execution adapter (release candidate)

English | [中文](README.zh.md)

`comfy_runtime.py` implements the Host's `qianshou.media-runtime.v1`: loopback listening only, private-token authentication, fixed reviewed image or video workflows, and fixed output paths. Task inputs replace only the text, reference images, or first and last frames permitted by the plan; users cannot submit node graphs, model paths, URLs, or arbitrary launch commands.

Each attempt is persisted in SQLite before its single `/prompt` submission, using the attempt UUID as the Comfy prompt_id in advance. After a lost response or process restart, the adapter only queries `/history/{原UUID}` and the original artifacts. Unknown requests keep the execution slot occupied; a timeout neither releases it nor triggers regeneration. A download failure resumes delivery of the original file only. The adapter does not modify existing image or video trial records, send media through Shanghai, settle payments, or generate earnings.

Upstream responses must have a bounded positive Content-Length, and results are written only after the number of bytes read exactly matches it. A partial file can resume only when it is a private regular file with a single hard link and its contents match the prefix of the original result. On Unix, the adapter fsyncs the parent directory after renaming the result and before committing success. Format magic provides only a minimum type check; Guangzhou independently performs complete decoding and verifies formal billing evidence. The CPU contracts verify an adapter process restart while the original history remains available; they do not prove end-to-end recovery after a Comfy backend restart, cleared history, or a machine power failure.

The installation package must contain this executable file, `recipes.json`, and the fixed workflow JSON files. Each recipes entry contains the exact cap5, fixed media parameters, workflow path, permitted input node fields, and a unique output node/collection. The workflow file SHA must match capability.workflow_sha256; profiles must exactly match the environment variables supplied by the Host from the reviewed installation manifest. Outputs use the same account's fixed directory `attempts/{attemptId}/result/{assetId}/result.png|mp4`; inputs reuse the Host's `attempts/{attemptId}/assets/{assetId}.png|jpg|webp`. The configured upstream allows only `http://127.0.0.1:端口`, with no proxy, redirects, or inherited upstream credentials.

Launch arguments: `--bind 127.0.0.1 --port {PORT} --token-file {AUTH_TOKEN_FILE} --instance-id {INSTANCE_ID}`. The main program path and recipes/graph must be included in Guangzhou's reviewed flat-file package; the program SHA is executor_sha256. This directory provides source code and CPU contract acceptance only: it has no reviewed release manifest, platform interpreter package, formal tiers/prices, or independent device acceptance receipt. Native Windows executable packaging, support for caller-specified prompt_id in the current 5080 Comfy service, and the authentication and original-task query contracts of H3/the unified API still require real acceptance. This candidate must not replace the active trial channel.

Run the CPU contract checks with `python3 -m unittest discover -s qianshou/media-runtime -p 'test_*.py'`. These tests use no GPU and create neither commercial orders nor device qualifications.
