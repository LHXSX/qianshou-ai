# @deepseek-ai/dsh-client-ui-qianshou

English | [中文](README.zh.md)

## Summary

The `qianshou` client build profile installs the user-supplied gold hands-and-chess Qianshou emblem, localized product name, and theme accent. The same emblem appears in the conversation hero, account welcome, and About view. The account menu owns the cloud-account link instead of a separate sidebar footer action. Other profiles receive no contributions. The plugin also provides a docked Agent tasks column over the live session catalog and opens existing child sessions in the right sidebar.

## Use this package

In calling mode the composer entry offers only image and video generation. Choosing one adds its reference to the existing draft and returns to the conversation; it neither submits a task nor requests payment. Users describe requirements in the conversation. CEO and skill creation keep the existing local skill, plugin and market board. Availability and actual execution remain owned by the media entry and Host. The sidebar Daily / Work control continues to select navigation, independently of the three conversation modes.

Ability cards accept one packaged static category-cover atlas; its images are decorative while names, source badges, prices and buttons remain real readable controls. No cover plays media or fetches a publisher URL. During a background market refresh, an existing callable card may start selection: the selector fixes the displayed execution contract and publication/owner/version/price identity, refreshes the authoritative catalog, and composes only if that identity still matches. It shows a checking state; changed, unavailable or failed reads preserve the draft and report refusal. Selection does not extend a quote or authorize payment.

The Web bundle mounts this package. Build with `DSH_CLIENT_BUILD_PROFILE=qianshou` and the public title `千手 PC · 开发版`. Contributions wait for their parent slots and disappear with the plugin or parent declaration. Both light and dark themes remain supported.

The expanded sidebar has a Daily / Work switch. Daily opens the ordinary conversation and hides work-only navigation; Work restores the last open work panel. This is a navigation mode within the existing PC profile, not a second session catalog. The composer Skills and plugins entry opens a large board with persistent search, primary content categories, metadata-derived subcategories, and ability cards. It reads current Session skills through `remote.skills.list`, active local plugins, and the reviewed market task catalog; source badges distinguish official abilities, user market, and local skills. Existing draft characters remain intact when a local skill or plugin request is selected. Market selection passes the originating Session and exact task type to `qianshouMarketSelection.refreshAndSelect`, whose market owner refreshes the same catalog used by the existing @ input path before composing a reference; refusal leaves the draft intact. Without the shared selector, the local entry remains available and the market catalog reports unavailability. Selection stays in the conversation and does not quote, execute, purchase, install, or open the market. Execution quotes and actual product buyout prices are labeled separately; zero-price products indicate free acquisition with execution priced separately, while local entries explain local execution and costs of external services follow their instructions, without claiming free execution. Opening reuses the current Session skill cache; explicit refresh rereads it. Host skill-file changes refresh mounted Sessions, while preset changes and connection resets invalidate skill lists.

The Community entry sits below Compute sharing. It reads the Guangzhou discussion service through seven fixed same-origin `/api/qianshou/community/*` JSON routes. Connection authenticates the local browser request first; the Host obtains the current Qianshou account access token for the upstream call, never exposing it to the renderer. The page lists server categories and topics, supports search, new topics, replies, author-only resolve, and reports. Official posts display the server's `official` flag. In the topic composer, choose Skill or Product, search the actual Host market catalog by name or purpose, then select a card. Product cards show the actual sale price and version. Selection keeps the topic draft and adds only its existing association; acquisition and purchase remain in the market. A linked task opens its exact current market contract; older local-skill links keep the existing skill search. Signed-out, unavailable, and empty states are distinct. The upstream origin defaults to `https://admin.qianshousuanli.com` and can be set to an HTTPS or loopback HTTP origin with `QIANSHOU_FORUM_API_BASE` in an isolated environment. Both request and response sizes are bounded by the Host proxy.

Linked topics resolve their display name from the full reviewed market catalog, including older posts. Internal product IDs remain navigation keys; unresolved entries show a readable unavailable message. The composer keeps the type selector compact, aligns the search controls, and scrolls search results separately.

Result images, GIFs and videos use the local same-origin `GET /api/qianshou/result-media?task_id=…&asset_id=<64-character SHA-256>&type=<media extension>`. Connection authenticates the browser request first. The Host asks Shanghai for a short viewer grant using the current Qianshou account token, then fetches media bytes directly from Guangzhou with that grant. Shanghai handles control metadata only; neither credential reaches the page. `QIANSHOU_RESULT_MEDIA_BASE` must explicitly name the Guangzhou HTTPS origin (or loopback HTTP); without it the route returns 503. The Shanghai origin defaults to `https://qianshousuanli.com` and can be set with `QIANSHOU_RESULT_MEDIA_CORE_BASE` for isolated environments. The Host requires one recognized media extension, matches Guangzhou Content-Type to that extension, permits at most 64 MiB, validates one byte range, length and Content-Range, and rejects redirects, HTML and compressed replies. For video links, it first checks the current Shanghai account and owner workload detail; a reviewed task can read only its matching MP4 result, while ordinary WebM/MOV tasks remain readable. Unknown or damaged review details fail closed before a viewer grant is requested. This proxy alone does not establish that Shanghai grants or the Guangzhou service are deployed.

Bounded ordinary files have a separate, default-closed Host route `GET /api/qianshou/result-file?task_id=…&asset_id=<64-character SHA-256>`. Set `QIANSHOU_RESULT_FILE_ENABLED=1`, `QIANSHOU_RESULT_FILE_BASE` to the exact off-Shanghai file-service origin, and `QIANSHOU_RESULT_FILE_CORE_BASE` to the control-plane origin after independent file-purpose enrollment. The current account obtains a signed 60-second owner download grant; Guangzhou reads the locked exact COS version through its dedicated `file-result` read identity. The Host validates the complete 28-field grant metadata, bounded length and actual SHA-256 and returns at most 16 KiB as `application/octet-stream` with `Content-Disposition: attachment`. Account changes, cancellation, timeout, extra query fields, public URLs, range requests and unsafe upstream headers are rejected; storage addresses and private grants never reach the renderer. It provides no HTML preview or media semantics. This candidate transport does not add a chat download control or prove deployed file execution, device admission, or delivery.

The task entry focuses an existing task tab across panes. New delegations and restarted child work reveal the column automatically; unchanged running tasks do not repeatedly reopen a dismissed column. It shows execution state and continuation mode separately, and the layout reserves space beside the main conversation. When a stored access credential is still unexpired, the Host turns on the in-window specialist that accepts assignments. The intake page owns the device master switch and reads the Host's installed skill/plugin inventory. Categories use explicit metadata; an installed item without a verified platform adapter stays visible but cannot be authorized. For `word_count`, the owner selects a verified local runner first and separately grants the `node` service. Selection and authorization do not guarantee live intake, orders, or income; the page also checks the current node admission reasons. Character or byte-count plugins do not qualify as word-frequency runners. This package does not start the builtin word-count process, refresh the account, or change model routes.

Intake refreshes retain the current source's cards, category, expanded details and scroll position while re-reading Host data. Only an initial read without data uses the full loading message; later reads show a small update or failure notice, with the affected item marked during a write. Retained eligibility cannot authorize intake: source selection, grants and author activation require a successful current read and the Host's fresh checks. Historical receipts and the conversation capability catalogs also retain their displayed data after refresh failures; stale catalog selection is disabled. A changed source, worker or owner identity clears its previous display and requires a fresh supply read. Display caches never extend a CNY quote or replace an execution grant.

Ordinary requests go through the conversation with their full history. The client no longer offers a single-sentence route preview beside the composer. The agent may inspect registered local and shared capabilities through read-only tools, then present a reviewable option in the conversation. Execution, package installation, paid orders and public supply keep their independent Host and owner gates.

When the agent saves a distributed compute draft, its replayable tool result becomes a conversation card. The card reloads the canonical local draft, lets the owner approve or cancel it, then requests a live Shanghai quote. It shows the exact server-recommended budget to be submitted, expiry, pricing basis and complete inline text before a separate owner click submits; actual charges and refunds are read from the task ledger later. An expired or unaffordable quote cannot submit, and an uncertain submission is never retried automatically. This client path does not create an order during ordinary chat or when the draft first appears.

The task list includes a read-only child file-change section. It shows the actual source child and turn, workspace, shared-edit warning, and retained-content availability. Available records open the existing review pane beside the conversation; missing or expired evidence has no working review link. Background task activity preserves the focused detail or preview when the sidebar is already expanded. Manual task navigation still focuses the existing task tab across panes.

The sidebar's former Help entry is Compute sharing, retaining its saved panel identity. It offers exactly two modes, image and video, with local model inventory, checked APIs and the Guangzhou connection as the primary observations. An authorized mode that is not ready offers Continue setup and sends a preparation command; a confirmed local API offers Pause sharing. Initial enable confirms the selected scope. The local Host owns hardware detection, existing model and service discovery, reviewed configuration matching, missing-file download, installation, loopback API and outbound Guangzhou connection; the renderer reads only a redacted status through `/api/qianshou/node/sharing/*`. Each mode separately shows generic local model inventory, checked runtime service and sharing qualification. Inventory is not mode qualification, and a missing reviewed configuration does not mean existing local models are absent or authorize downloading them again. Reuse and adoption labels require the Host's verified file and runtime observations. The page owns a height-constrained vertical scroll area inside the main column, including on small windows; short desktop windows also use compact spacing. A disclosure shows seven setup stages. Calls and CNY earnings come from unique settlement receipts and the actual ledger; unavailable values remain unknown. Account changes clear prior receipts, and an unknown command outcome is reconciled by GET without replaying the POST. Official model releases and real device qualifications remain independent deployment prerequisites.

Enable and resume open a short confirmation only when the selected mode lacks current device-bound idle authorization. It permits outbound Guangzhou connection and idle-only execution, explains pause, prioritizes verified reuse of existing resources, and guarantees neither orders nor earnings. The confirmation or an explicit preparation click reusing that current authorization sends `consent: { version: 'qianshou.media-sharing-consent.v1', connection: true, execution: 'idle_only' }` with the original mode, request UUID and Host `scopeId`. This independent media authorization leaves the legacy tool master switch and grants untouched. Pause stops new intake; an additional revocation action removes the mode's grant. Account changes clear the dialog and unknown operation, and stale dialog callbacks cannot confirm another scope. The controller consumes each dialog before writing, keeps the original UUID after an unknown POST, and only queries `status?request_id=UUID`; exact `not_found` permits another explicit action, with confirmation when current device-bound authorization is absent. Older desired state never upgrades permission, and an unscoped legacy Host remains readable but cannot grant sharing. Connection permission, idle execution permission, reviewed model/device qualification and actual sharing remain distinct. A running Mac research API or local model inventory does not establish production qualification. Missing reviewed plans, unavailable resource observations and execution vetoes stay visible as blockers.

When an authorized device also lacks a reviewed plan, the card explains that missing plan before the idle gate; an idle observation alone does not imply the setup is ready. An idle, blocked or failed mode with current device-bound idle authorization offers Continue setup. It sends a scoped enable command to recheck local resources and prepare the connection. The controller reuses only the selected mode's current authorization; revoked, partial or unbound permission requires confirmation. A fresh Guangzhou-confirmed API offers Pause sharing. Preparation progress appears on the main card, and only the selected command displays Processing. Unknown writes retain their original UUID without a new preparation POST. A current local API plus authorized connection and accepted heartbeat displays a trial connection with no platform fee, even when paid-task adoption remains unverified. It does not establish Guangzhou API confirmation or a successful generation. Reviewed configurations, tiers, device qualification and paid-task blockers remain in a separate collapsed disclosure. Missing local services stay unavailable, and automatic preparation of an absent API is not claimed as implemented.

The optional per-mode API observation projects a fixed adapter, friendly model/workflow labels, registration state and the last actual metadata roundtrip receipt. Missing fields stay unknown. Guangzhou confirmation requires current scoped authorization, the accepted channel/heartbeat and a registered passed receipt newer than 120 seconds; local health alone cannot establish it. A failed read or account change withdraws prior confirmation. Unknown fingerprints remain unknown, and API metadata does not publish paid capabilities or generate a task.

The sharing controller reads at PC startup and every five seconds. Status reads return the current owner-scoped observation promptly and trigger background discovery and a public Guangzhou probe against the bootstrap domain. They do not queue behind model startup, GPU execution or long metadata requests. Reachability, authenticated device connection authorization, task channel and accepted current-epoch heartbeat are separate observations. Anonymous users can see gateway reachability. Local service readiness alone cannot show active task sharing; that label also requires verified resource adoption, the current authenticated authorization, connected channel and accepted heartbeat. The renderer receives only finite states and timestamps, with no private address, model path or credential. A ten-second local-read deadline also covers IPC that ignores cancellation. Failed reads display Detection incomplete and Detect again, discard late replies, and withdraw the old connected and local service indicators while preserving known mode statistics; account changes clear the previous account and discard late responses. The notice distinguishes a missing Host route, local status timeout, sign-in failure, unavailable Host, and incompatible response using bounded HTTP/error codes without showing server text or addresses. Legacy Host responses without local discovery or connection fields remain unknown.

## Model Experience

### Delegation messages

#### What the model sees

The `subagent` runtime remains the source of task status. The Delegation settings view lets a user choose automatic, one-shot, or continuable execution and a specialist or custom role. Submitting sends an ordinary visible user message to the scoped CEO session; it leaves the main composer draft intact. The recorded request includes the selected lifecycle, role, objective, and acceptance requirements. It uses ordinary model calls and token billing. A queued request is not evidence of delegation or completion: task cards continue to report the actual Host descriptor. There is no new tool or persistence format.

#### Token effect

A submitted delegation adds an ordinary visible user message and its normal token cost; rendering task cards adds no model requests.

#### KV Cache effect

Delegation appends through the ordinary Session input. It does not rewrite past messages or introduce another prompt prefix.

## Known Limitations and Deferred Work

<a id="known-limitations-and-deferred-work"></a>

The Qianshou profile uses the existing theme override layer for coherent light and dark backgrounds, panels, sidebar, text and fine borders. User settings continue to control font and theme preferences. The layer is removed on unload and is not registered by the official profile. Category covers use the business-independent shared static `ui-primitives/SkillCover`; the market and conversation picker share one atlas and mapping. Names, prices, approval and availability remain live accessible DOM rather than being drawn into decorative images.

- The cloud link opens the existing website; it does not transfer browser login into this local profile. The task window does not equate inactive execution with accepted work; specialist labels come from CEO delegation descriptions. Device pairing, capability pricing, and account sign-in remain separate work. Desktop installer identity and updates require separate release configuration. No invariant companion is published because all contributions have one owner and their removal is verified by lifecycle and assembled UI checks.
- Daily and Work currently share the underlying conversation and workspace catalog. Independent mode histories, separate daily tools, timed plans, and connection marketplace behavior need their own product services before the two modes can match the researched reference end to end.

Ability selection calls `SessionInput.composeReference()` with the originating Session input revision to insert plain prefix text. It preserves atomic file and Session references and changes an unsent command without losing its arguments. An ordinary running Agent does not block draft selection; command admission and adjudication keep their brief input lock. Catalog refreshes cannot write into a replaced Session binding.

Approved author skills show “Approved · orders not enabled” until a fresh inventory confirms device eligibility, a coherent saved grant, and an enabled master switch. Listing status appears separately, including missing sales materials or an explicit one-time price. Enable orders invokes the existing Host activation only after an owner click; refreshes and rendering never install or submit. Cached or unavailable eligibility cannot display enabled intake or authorize actions.

The optional profile service `qianshouMarketplaceNavigation.openPublications({ source, name })` opens existing publication management for one canonical local skill identity. A true return means the request was accepted, not that a publication exists or was read. The manager retains only the latest opening request before mount and consumes it by request ID. An older acknowledgement cannot discard a newer request; consuming a request preserves the workspace’s chosen tab and exact source focus. Disposal invalidates retained callbacks. Navigation does not set prices, publish, approve, purchase or enable intake.

Each capability check locks only its own card. Changing the choice, closing the board or reaching the configured `abilitySelectionTimeoutMs` cancels that selection; a late catalog reply cannot compose a reference. The client plugin accepts an integer timeout from 1000 to 60000 milliseconds (default 15000). Other available cards and refresh remain usable during a check. This waiting limit never approves or cancels a paid task.

The local plugin board uses `conversationPlugins()` to read only installed bundles and active Loader rows, without waiting for cloud publications, entitlements or device installation inventories. Names prefer the installed package’s `qianshouDisplayName`; market task IDs, skill commands and plugin identifiers are collapsed under Technical details. Refresh preserves existing cards without disabling the entire source. Selection still checks fresh local state, only the chosen item waits, and execution is never claimed without a real tool receipt.

For generated `qianshou-local-` package titles with the generator's exact 32-digit hexadecimal suffix, the card uses a compact heading from the public description or the localized Local plugins label. Human-written names stay unchanged; Technical details, borrowing drafts and Host selection keep the original title and identifier.

The intake page’s H3 setup card reads the current authenticated owner and profile only after it is opened. The owner chooses existing model, workflow, first-frame and runtime files, plus the adapter’s actual video output folder. Checking and saving do not generate video. An explicit local test generates a five-second video without platform billing; pending or unknown tests are never automatically retried. A verified local trial can create a local skill draft, while platform review, publication and device supply permission remain separate. The Host issues an opaque setup context for the exact owner, profile and configuration revision; start and draft requests reuse it rather than accepting a caller-selected owner. Account invalidation clears the card, and late callbacks cannot restore old selections or trial evidence. Private paths and raw failure details are not rendered.

The intake page first summarizes the current Host inventory across all installed capabilities. It counts locally eligible sources separately from sources needing order setup; an incomplete or failed read leaves both counts unknown. Model-specific setup follows the inventory. The canonical H3 card lists ComfyUI/H3 service, five model roles, plugins and the four-step workflow only after the owner opens that card. Their displayed state reflects only a whole-service identity inspection or prior local video trials; it does not infer which particular file is missing or represent live order eligibility. A saved configuration without a current inspection returns to “not verified.” The card gives manual installation guidance because no verified signed download source is configured. It never downloads software or enables intake; the Host verifies the installed adapter again when a reviewed video order source is selected.

The intake browser has three presentation groups, Tools, Images and Text. Existing category and eligibility metadata stay intact; legacy video tools remain visible in Tools. Counts reflect the installed inventory, not an assumed 64 verified tools. Clicking a group again clears the filter. One button opens Compute sharing; manual H3 configuration is collapsed as legacy diagnostics.
