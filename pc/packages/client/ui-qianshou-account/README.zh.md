# @deepseek-ai/dsh-client-ui-qianshou-account

[English](README.md) | 中文

## 概述

在千手设置中使用密码或短信登录，完成要求的两步验证，并从个人中心或侧栏管理当前账号。读取真实套餐、余额与五小时用量；订阅和充值都需要明确确认。切换账号和退出登录也先确认。扫码登录及永久注销在真实服务接通前保持不可用。普通上游构建不注册这些入口。

<a id="interaction"></a>
## 交互

侧栏头像显示用户名与 Host 鉴权状态，桌面版本和更新操作占用安静的第二行。菜单按账号、用量与套餐、设置、桌面更新（载体支持时）、千手云、帮助、关于、退出登录组织；关于页提供协议和隐私入口。未登录的设置页居中显示登录卡，使用 Host 所有的 `qianshouAccount` Remote 完成密码、短信及要求的两步验证。

密码与一次性验证码仅保留在已挂载表单中，在提交或取消后清空。共享界面存储只包含安全的 Host 状态与请求进度；认证、计费、支付错误分别显示。后续用户操作替代早期响应，因此迟到的界面结果不能撤销取消登录。两步验证卡片提供明确的取消操作。

可恢复的 Host 账号在每个 Client 生命周期内自动重连一次。侧栏轮询仅读取状态，不反复触发网络续期。重新连接显式验证身份并刷新真实模型目录。临时故障保持可见，界面不会仅凭配置了密钥就推断已登录。套餐、额度或余额读不到时显示暂未获取，不填示例数字。订阅需要先获取 Host 报价再单独确认；充值仅在用户主动操作后提交 Host 返回的支付宝表单。

登录不选择模型提供方。独立的“使用千手模型”操作改变新会话和此前未选择模型的空会话默认值。界面同时说明该影响和开发凭据文件为明文存储。[Host 包](../../host/qianshou-account/README.zh.md) 负责身份认证、凭据持久化、网关验证与取消。

个人中心用四张卡片分别展示套餐及可用 SP、人民币余额、五小时用量和接单记录入口。卡片沿用 Host 的真实读数，接单收入仍以平台结算记录为准；套餐和充值入口只打开相应流程，不直接支付。表单、报价确认及原订单核对保持可见，页面共享设置外壳的滚动区域。

个人中心直接提供「切换账号」和「退出登录」，两者都先确认再调用现有 Host 退出接口；侧栏菜单复用同一确认。确认绑定打开时的账号，期间身份已切换就不能退出新账号。真正退出后回到现有登录表单，连接失败保留提示。退出清除本机凭证并尝试现有服务端退出；接单准入在既有身份核对后关闭，本界面不承诺所有运行任务即时撤销，也不删除原保存授权。已发布技能、订单和余额仍留在平台。这里没有普通用户永久注销的 Remote，不展示假成功操作。

<a id="model-experience"></a>
## 模型体验

### 账号展示与路由准入

#### 模型看到什么

`qianshouAccount` Remote 是主人界面接口。账号面板是产品界面，不提供模型工具，也不添加对话消息。Host 返回的身份与故障状态决定显示内容，模型不能声称自己已经登录。

#### Token 影响

账号操作与界面展示不会发起模型请求或增加提示词 token；后续对话使用明确选定的模型路由。

#### KV Cache 影响

本包不重写既有消息，也不注入隐藏提示词前缀；缓存行为由选定模型提供方与普通对话流程决定。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- 组件测试驱动账号密码与短信提交、TOTP、取消竞态、恢复、显式路由选择、账号与计费错误隔离、账号菜单导航。真实用户登录、支付完成与广州推理属于独立集成验收。本包不发布运行时 invariant 伴随插件，因为本包不拥有独立的账号事实，只投影 Host 响应。
