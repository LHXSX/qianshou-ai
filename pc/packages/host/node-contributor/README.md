# Qianshou node contributor

English | [中文](README.zh.md)

## Summary

`@deepseek-ai/dsh-host-node-contributor` is the provider-neutral controller for a local agent that has explicitly enabled compute contribution. It inventories self-tested capabilities, publishes a minimal heartbeat, admits verified offers autonomously under the existing contributor policy, binds each accepted attempt to a node lease, and emits a pending billing ledger reference only after core acceptance evidence exists. The package does not create another queue, settle money or invent a Shanghai assignment signature.

## Control-plane boundary

`inventory()` exposes capability IDs, versions and plugin digests plus bounded capacity. The advertised projection has explicit privacy guarantees and contains no user file list, local path, prompt, credential, media byte or upload URL. A concrete dispatch adapter owns authentication and transport; Shanghai receives control metadata only.

`acceptOffer()` requires the process-local verification credential minted by `compute-core` and checks exact task, attempt, expiry, owner and idempotency bindings in the node lease. Capability data scope and input/output byte limits are checked before the shared `EmployeeTaskCoordinator` and `ComputeTaskStore` admit work. Accepted work is marked autonomous and has no human approval callback.

`pause()` and `revoke()` publish local state only after the existing task store commits the transition. A refused transition preserves the previous visible state and lease. The host must stop and drain execution before reporting a pause or revoke; this controller owns no executor. `reportCompleted()` forwards a core-confirmed pending earnings reference without mutating a ledger or initiating payment.

The package composes `compute-core`, `dispatch-adapter`, `platform-foundation` and `billing-contract`. When `allowedTaskTypes` lists types this process can run, the plugin binds the HMAC inline Edge connector, including while contribution is off.

The hello repeats only the owner's public, exact built-in `qianshou.article@1` market declaration for `text.transform`: a `draft`, `private` or `invite` row stays on this computer, a row whose `visibility` is absent or unrecognized reads as a draft, and package-backed or unknown rows cannot borrow the built-in runner even if they declare the same capability id. `image.generate` is never advertised because this process cannot run it. The capabilities this process runs itself are advertised whether or not a market row mentions them, and the invite account ids saved beside a row are not read here.

## Authorization and shutdown

The constructor copies the owner's authorization limits. `acceptOffer()` combines them with the current per-offer policy using the stricter limits; an offer cannot broaden the owner's authorization. Either policy being `OFF` refuses new work. Foreground or voice activity and unavailable resource facts are checked by the existing contribution policy. A temporary refusal remains retryable when the host becomes idle.

A controller configured `OFF` publishes an empty capability advertisement and remains `DISABLED`. Installed capability descriptors remain available for local inspection. Per-offer restrictions apply to that invitation; replacing the controller's configured deployment ceiling requires constructing a new controller. Saved owner preferences take effect through the resident plugin's per-offer policy. Disabling future admission does not cancel an already admitted task.

The resident plugin reads the complete saved `SupplyPolicy` before connecting and before each tick. `off`, unavailable authorization, foreground work, voice activity or unknown activity facts pause new intake. `idle` additionally requires the saved `minIdleSeconds`; `allowed` still respects the deployment's foreground-use restriction. Free memory must meet `minFreeMemoryBytes`, and admission uses the smaller owner/deployment concurrency limit. These restrictions affect buffered offers as well as incoming Edge frames. Existing attempts and result delivery continue.

`autoStart` defaults to true; the resident driver waits for credentials and retries connection failures. Registration reports measured inventory, while the owner's saved supply policy controls new admission.

Service selection applies to executable capabilities: selecting `node` permits a verified inline `word_count` runner or an explicitly bound `text_sort` runner (`text.transform`). Unbound service-to-runner mappings cannot authorize work. Internal heartbeat capabilities use the same decision as admission. Edge heartbeats carry its paused/running state and measured load; their protocol carries no dynamic capability list, so the hello inventory remains a machine inventory. When a lowered concurrency limit is below the number of existing attempts, the heartbeat capacity includes those occupied slots until they drain; local admission retains the lower limit.

The owner can choose one installed, enabled profile plugin with an explicit inline order contract from the intake page. The legacy `localTextStatisticsPackageName`, `localTextStatisticsToolName` and `localTextStatisticsPackageDigest` settings remain an initial-selection fallback. Install origin does not grant or deny eligibility: a bundle needs either the exact legacy version-1 `word_count` adapter or a version-2 adapter with task type, `inline` input, `inline_json` output and `v1` contract, a self-contained package without install scripts or external dependencies, an active Loader entry and a matching installed-tree digest. Inventory reads only these static facts and never runs unselected plugins. Explicit selection runs a five-second total output probe across contract fixtures and saves a profile-private choice; it does not grant intake. The owner must revoke the `node` grant and let in-flight tasks drain before switching. The active Host runner changes immediately without a YAML edit or restart. Re-granting performs another sample, and each order checks loading, digest and task-specific output before delivery. The old character counter has no order adapter and remains ineligible. `text_sort` is the second contracted task, tested for default sorting, reverse numeric sorting and deduplication; the platform's default `single_file` input does not match this inline-only Edge bridge. This profile-plugin selector handles inline text; native media uses the shared command/artifact execution contract below. The global tool registry exposes no package owner for a name, so Loader state and digest alone cannot prove which bundle registered that tool; the sample and per-order output checks are further rejection gates. Local selection and authorization are not marketplace purchase, platform pricing or a paid dispatch receipt.

`GET /api/qianshou/node/status` reports `declaredCapabilityIds` from the resident capability projection and `acceptingCapabilityIds` from the capabilities admission marks available. Owner policy `off` keeps the declaration and leaves acceptance empty. This projection does not add a platform dispatch signature.

`close()` rejects new operations, closes the shared coordinator and waits for in-flight transport callbacks. Late completion cannot restore an online state. The caller retains any already committed task record for reconciliation; shutdown does not manufacture a cancellation or completion receipt. Transport adapters must bound and finish their callbacks because this controller cannot abort them.

## Device-owned market runtimes

A reviewed author publication alone is never a Hello claim or an execution route. Authors and buyers both use server-held entitlements, signed source bindings, installed bytes and a current device receipt through `verifiedPurchasedOrderRuntimes`. A verified inline runtime may qualify the existing `node` service while retaining the owner policy, master switch, activity and admission gates. Its proof never substitutes for the selected default runner's own sample: default task claims still require that runner to pass. File schemas do not authorize file execution through this inline path.

Proof calls use the current Cordis context proxy. The service and provider/runner checks across an awaited proof compare the stable `symbols.original` service and its original methods: repeated proxy reads have different identities. A replaced service or changed method still discards that proof; an unchanged traced service keeps its verified claims without reconnecting on every tick.

An empty first inline proof is not cached permanently: account recovery or a temporary source-read failure may later return a verified runtime. The existing Hello retry starts after five seconds and doubles to at most sixty seconds; no claim appears before the current provider verifies it, and a successful snapshot stops periodic reconnects. The same worker identity, signed installation/device receipts and owner admission policy remain required. Retrying inventory never changes grants, creates an order or executes a task.

## Model Experience

### Isolated task input

#### What the model sees

When an isolated agent runner is invoked with an explicit provider and model, admitted types use a fresh session unless the owner explicitly bound a local plugin or a purchased runtime for that task. The user message is the admitted prompt and nothing else. The assistant reply is carried back on the `word_count` landing in `result_lines` and `summary_text`. The session gets no parent seed. Setup mounts the host's default agent preset, so the specialist can run that preset's shell and files under the host sandbox and approval. Its header cwd is a new private directory outside the owner's attempt storage; the directory is removed after the turn. Deployment prompt text can resolve `{{cwd}}` without revealing the owner's workspace root to the model. Before delivery, unrequested local home and attempt paths in the assistant reply are hidden; paths the customer supplied in the assignment remain intact. The local `word_count` counter runs only when neither the route nor a selected plugin is available. Rejected offers make no model request. `isolatedReasoningEffort` controls only this task session. The shipped Qianshou route sets `off`, independently of the owner's CEO thinking control. An empty value leaves the selected adapter's default; the adapter and model must support the selected effort.

#### Token effect

The isolated request sends the admitted prompt and no type label. Input-dependent token count varies with that prompt; this package adds no parent history. Heartbeats, policy reads, the deterministic word-count runner and the pinned local plugin contribute zero model-input tokens.

#### KV Cache effect

Each isolated task creates an independent session and appends its input there, without changing the foreground session's reusable prefix. Different task inputs, provider routes or model selections may change request-prefix reuse; provider cache availability and eviction remain outside this package.

## Known Limitations and Deferred Work

<a id="known-limitations-and-deferred-work"></a>

- With `isolatedProvider` and `isolatedModel` set, admitted types run in the isolated session except a text landing explicitly bound to the pinned local plugin; none inherit the CEO default route. Without either route, `word_count` runs locally. AT-01 two-machine return remains unbound. Types without a local runner or that route fail at load.
- The local plugin order binding covers only the existing text landing in this Host. It does not create a Shanghai marketplace listing, buyer entitlement, price, platform install receipt or public dispatch authority. A real customer order still needs an end-to-end platform acceptance receipt.
- Isolated agent routes do not yet have a verified binding to owner-selected local services and remain unavailable for resident admission. Installing or selecting a tool does not authorize an unrelated model account. Unknown required activity or memory observations pause new intake.
- The private cwd and result guard prevent accidental owner-path disclosure in ordinary replies; the mounted host preset still has its existing tool permissions. General-purpose external orders require a verified per-task filesystem sandbox before claiming file isolation.
- Inventory readers and dispatch adapters are deployment-owned and must provide trusted local facts; unavailable resource facts must fail closed before admission.
- Earnings are references to a core-confirmed pending ledger entry. Pricing, settlement, refunds, tax and withdrawal remain owned by the commercial system.
- Policy tests use isolated stores and controlled transports; media checks also use actual temporary HTTP/SQLite and subprocesses. These prove mechanisms, not production node or payment acceptance.
