# 千手节点贡献控制器

[English](README.md) | 中文

## 概述

`@deepseek-ai/dsh-host-node-contributor` 是本机智能体明确开启算力贡献后的提供方无关控制器。它盘点已自检通过的能力，发布最小心跳，在既有贡献策略下自主准入已验证邀请，把每次接受绑定到节点租约，并且只在核心验收证据存在后发出待处理计费账本引用。此包不创建第二套队列，不结算资金，也不编造上海 assignment 签名。

## 控制面边界

`inventory()` 只暴露能力 ID、版本、插件摘要和受限容量。上报投影带有明确的隐私保证，不含用户文件列表、本地路径、提示词、凭据、媒体字节或上传地址。具体调度适配器负责鉴权和传输；上海只接收控制面元数据。

`acceptOffer()` 要求 `compute-core` 在本进程签发的验证凭证，并严格检查节点租约中的任务、尝试号、过期时间、所属节点和幂等键。能力数据范围以及输入/输出字节上限在共享的 `EmployeeTaskCoordinator` 和 `ComputeTaskStore` 准入前检查。已接受任务标记为自主执行，不包含人工审批回调。

`pause()` 和 `revoke()` 只在现有任务存储提交转换后更新本地状态。转换被拒绝时，原有可见状态和租约保持不变。宿主必须先停止并排空执行，再报告暂停或撤销；此控制器不拥有执行器。`reportCompleted()` 转发核心已确认的待处理收益引用，不修改账本，也不发起支付。

此包组合 `compute-core`、`dispatch-adapter`、`platform-foundation` 和 `billing-contract`。`allowedTaskTypes` 列出本进程能跑的类型时，插件绑定 HMAC inline Edge 连接器，包括关闭贡献时。

hello 只会重复主人公开的精确内置 `qianshou.article@1` 市场声明，对应 `text.transform`：`draft`、`private`、`invite` 记录留在本机，`visibility` 字段缺失或本版本不认识的记录读作草稿；包型或未知记录即使声明相同的能力 id，也不能借用内置运行器。`image.generate` 永不上报，因为本进程跑不了它。本进程自己能跑的能力照常上报，与市场里有没有对应记录无关；记录旁边保存的邀请账号 id 在这里不被读取。

## 授权与关闭

构造函数复制主人的授权上限。`acceptOffer()` 将它与当前邀请的策略组合，采用更严格的限制；邀请不能扩大主人授权。任一策略为 `OFF` 时拒绝新任务。前台或语音活动以及不可用的资源事实由现有贡献策略检查。临时拒绝的邀请在宿主空闲后仍可重试。

配置为 `OFF` 的控制器发布空能力广告并保持 `DISABLED`。已安装能力描述仍可供本机检查。邀请策略只限制该次邀请；替换控制器配置的部署上限需要构造新控制器。保存的机主偏好通过常驻插件的逐邀请策略生效。禁止后续接单不会取消已接受的任务。

常驻插件在连接前及每拍开始前读取完整的已保存 `SupplyPolicy`。`off`、授权不可用、前台任务、语音活动或未知活动事实均暂停新接单。`idle` 还须达到保存的 `minIdleSeconds`；`allowed` 仍遵守部署方对用户活动期间接单的限制。可用内存须达到 `minFreeMemoryBytes`，接单采用机主与部署方中更小的并发上限。这些约束同时检查已缓冲邀请和新到达的 Edge 帧，既有任务尝试与结果回传继续执行。

`autoStart` 默认为 true；常驻驱动等待凭据并重试连接失败。注册报告实测机器清单，机主保存的供给策略控制新任务准入。

服务选择约束可执行能力：选中 `node` 才能使用已验证的进程内 `word_count` 或已绑定的 `text_sort` 等精确 inline 执行器（`text.transform`）。尚未绑定的服务与运行器不能据此授权接单。内部心跳能力与准入采用同一决定。Edge 心跳携带暂停或运行状态及实测负载；协议不包含动态能力列表，因此 hello 清单仍表示机器资源。当机主降低的并发上限小于既有任务数时，心跳容量包含尚未结束的已占槽位，本地准入仍严格采用较低上限。

机主可通过接单页，从已安装且启用的 profile 插件中选择一个明确声明契约的 inline 执行器；旧配置的 `localTextStatisticsPackageName`、`localTextStatisticsToolName`、`localTextStatisticsPackageDigest` 仍可作为初始选择。安装来源不参与准入：包必须声明精确的 `qianshouOrderAdapter`（旧版 1 仅 `word_count`；新版 2 还需 `taskType`、`inputKind: inline`、`outputKind: inline_json`、`contractVersion: v1`），自包含且无安装脚本或外部依赖，已由 Loader 激活，并通过安装树摘要核对。浏览安装清单只做这些静态检查，不执行插件；点选时再运行总计限定 5 秒的任务契约输出自检，保存 profile 内的选择，但不自动授予接单权限。先撤销已有 `node` 授权且没有执行中任务，才能切换执行器；成功后当前 Host 的派单运行器立即切换，无须手改 YAML 或重启。重新授权时再次自检；每个任务执行前后核对加载与摘要，实际输出必须通过对应平台任务的独立校验。旧字符统计插件无此适配声明，不能承接词频订单。当前新版适配的第二个真实任务是 `text_sort`，对排序、数字逆序和去重等输入运行自检；仅支持 inline，平台默认的 `single_file` 仍不能匹配。此 profile 插件选择器处理内联文字；原生媒体使用下述共享命令与产物执行合同。工具注册表没有公开的包归属字段，故摘要和 Loader 状态不能单独证明同名工具由该包注册；输出自检与逐单校验是额外的拒绝闸门。选择与本机授权不代表市场购买、平台报价或真实付费派单回执。

接单声明采用来源中立的 `task-adapters.v1`：每个经过本机契约自检的执行器在 Hello 中单独声明平台任务类型、能力 ID、可接收的输入形式、输出形式、版本、安装状态和当前加载代码或包的 SHA-256。上海只按精确任务类型和输入形式筛选；购买、自制、导入的区别不进入匹配条件。内联文字声明路径只接受对应内联结果；文件与媒体必须通过各自已验证的执行 ABI 进入同一常驻派单链，不能凭技能清单声明。机主授权仍由实时心跳和本地准入检查控制。安装、卸载或切换执行器后必须重新建立 Edge 会话发送新的 Hello；旧快照不能代表新执行器。

`GET /api/qianshou/node/status` 上报常驻能力投影里的 `declaredCapabilityIds`，以及准入标为可用的 `acceptingCapabilityIds`。机主策略为 `off` 时保留声明，接单列表为空。这份投影不补平台派单签名。

`close()` 拒绝新操作，关闭共享协调器，并等待正在进行的传输回调。迟到完成不能恢复在线状态。调用方保留已经提交的任务记录以便对账；关闭不会伪造取消或完成回执。传输适配器必须限制并结束回调，因为此控制器不能中止它们。

## 有设备权益的市场运行时

作者投稿审核通过本身不构成 Hello 声明或执行路径。作者与买方统一通过 `verifiedPurchasedOrderRuntimes` 核对服务器权益、签名源码绑定、已安装字节和当前设备回执。已验证的内联运行时可以成为原有 `node` 服务的资格依据，但继续遵守所有者策略、总开关、活动状态及准入条件。它的证明不能代替当前默认执行器的样例：默认任务仍须由对应执行器自检通过才能声明。文件 schema 不会通过这条内联路径取得文件执行授权。

证明调用继续使用当前 Cordis 上下文代理。等待证明前后的服务与 provider/runner 检查比较稳定的 `symbols.original` 服务及其原始方法：重复读取代理会得到不同身份。服务被替换或方法改变时仍丢弃该证明；未改变的追踪服务保留已验证声明，不会每轮 tick 都重连。

首次内联证明为空时不再永久缓存空结果：账号恢复或临时源码读取故障结束后，可能重新取得已验证运行时。既有 Hello 重试从五秒开始，间隔加倍至最多六十秒；当前 provider 核验成功前不声明能力，成功快照会停止定期重连。仍需同一 worker 身份、签名安装和设备回执，以及机主准入策略。重读清单不会改变授权、创建订单或执行任务。

## 专用文件 provider 准入

当前 catalog 同时提供动态运行时 provider 与对应 runner、但尚无已验证适配器时，Host 可认证一个空能力设备会话，用于记录独立安装挑战。每次连接都重新读取这两个端口。内部注册模式发送空能力数组、始终暂停，并拒绝任务交付、执行及运行请求。静态空配置仍拒绝连接。取得已验证回执后，重连通过普通会话声明 provider 给出的精确已安装能力；认证本身不能成为 `node` 服务资格或开启贡献。

当配置集合仅含明确声明的固定产物 provider 且均无就绪适配器时，只有当前 catalog 明确允许，才能使用上述仅元数据注册。机主因而可以先完成设备认证，再保存 H3 私有配置或完成试片。普通或未知任务类型不能借此例外注册；已就绪的固定适配器沿用普通声明会话。保存配置本身不会开放别名：显式原生刷新仍须核对实际 provider 身份、设备用途签名和同一当前连接的 ACK。Loader/套接字测试读取真实机主配置的 schema 文件，模拟固定运行器与真实 GPU 验收继续分开。

候选 `purchasedFileTaskAdapters` provider 独立于普通 inline 声明，并且要求文件 runtime 消费者。其 catalog provider 在每次 Hello 前验证当前账号/设备归属、已签不可变安装与专用文件设备回执。检查失败时，重连会同时移除文件声明及运行能力。消费者通过认证 resident session 的当前租约申请附件授权并上传输出；缺文件元数据时不会回退到 inline 运行器。机主策略、空闲准入、取消、独立结果核验及结算继续沿用已有生命周期。文件源码测试不能证明生产节点回执，仍需用途登记并加载本段候选。

## 显式连接广州媒体会话

`mediaGatewayOrigin` 默认为 `https://app.qianshousuanli.com`；显式空值关闭公开探测，并显示未配置。媒体路由保持认证要求；只有机主显式连接已配置的 HTTPS 广州入口或直接回环联调服务，才会登记节点。本机发现只从直接回环地址读取有界的 Comfy 清单，返回模型标识和内存事实，不启动工作流，也不形成派单就绪证明。另行安装的 `qianshouMediaNodeExecutor` 必须提供已核验 profile、遵守机主策略的资源事实与持久租约准入。没有该执行器时，注册不声明 profile，心跳报告零空闲槽。此会话不提供上海报价、支付或结算权限。

显式连接按经过校验的 `mediaReconnectInitialMs` 与 `mediaReconnectMaxMs` 范围，对临时网络故障执行带抖动的重连。`mediaRequestTimeoutMs` 默认 30000，`mediaChannelWaitMs` 默认 10000，`mediaDiscoveryTimeoutMs` 默认 10000；完整请求期限必须至少比长轮询等待多 1000 ms。恢复先读取原收件箱，再发布容量。准入必须先持久保存原 attempt，再确认游标，使重放能核对原任务且不重复执行。此传输不拥有 GPU 执行，也不能代替执行器的崩溃恢复证据。

每条通道捕获原始 provider 身份、revision、复制后的 profile 摘要及并发上限。账号切换、provider 替换或这些事实的原地变更都会停止重连并撤回旧通道；显式连接才重新捕获事实。profile 或并发事实改变时须使用新的能力 revision。断开和卸载请求广州撤销，并在确认后把远端容量归零。状态在 `errorCode` 保留原始失败，另用 `withdrawalConfirmed` 表示撤销结果：当前 epoch 尚未撤销为 null，只有广州确认离线才为 true，尝试未确认则为 false。合法的新 epoch 持久保存后才重置为 null。撤销失败时，远端心跳过期仍是活性边界。

设备凭据与收件箱游标保存在 Harness home 下按机主与来源隔离的目录，与账号凭据分开。状态不包含设备令牌或任务输入。POSIX 目录使用 0700、文件使用 0600，并执行文件同步、原子重命名及父目录同步。Windows 硬件断电持久性尚未验证。真实广州 HTTP/SQLite 源码夹具覆盖协议恢复与撤回，不代表服务已部署、Windows 执行器已安装、GPU 已出片或付费订单已完成。

## 机主配置的原生媒体

`command-artifact.ts` 提供共享原生命令 ABI：适配器只提供机主本机调用、严格输入合同及正规化输出清单；运行器核对工作目录范围、实际字节和 SHA256。既有常驻产物消费者使用已认证节点租约直传 COS/广州，验证服务端签发的不可变产物元数据，再通过原有 Edge 会话返回引用。技能不另建派单、上传或计费通道。

V1 H3 使用明确的私有 `H3_OWNER_CONFIG_PATH`，填写真实 Python、FFmpeg/ffprobe、固定节点入口与 runtime、模型、工作流 JSON、PNG 首帧和 `outputRoot` 位置。loopback 来源由机主配置，不固定电脑或端口。固定 `qs_new4` reader 以实际 PNG 和固定 negative UTF-8 字节的 SHA 调用 `/v1/recipes/qs_new4/identity`，拒绝重定向，将响应限为 64 KiB，并核对精确配方字段和五个权重角色。原生准备要求该接口实际生成配方与模型字节的 SHA，以及 `nativeBinding` 与这些身份一致的先前真实试片。UI 工作流 JSON、模型文件属性、服务健康和旧成功视频都不能替代这些身份。缺少实际身份接口会拒绝准备；真实试片须保留供复验。

`nativeH3AuthorBinding()` 只返回五项 V1 公开身份，不生成作业。`selectNativeH3AuthorBinding()` 核对精确的纯 JSON 源包，仅返回本机验证，不授予平台审核或接单权。已发布任务别名要求用途独立、当前机主与 ACK 设备精确匹配的回执，并核对投稿源码、上海合同快照和私有配置。只有固定 H3 工厂能将别名加入 Hello 与媒体桥。每次执行都重核当前身份、回执期限和真实配置，向固定运行器传入配方、模型预期摘要，拒绝每作业实际身份不匹配。买方只填内联描述、固定五秒和可选 seed；16 MiB MP4 复用既有直传媒体路径。既有机主策略仍控制接单。

`runNativeH3ReviewChallenge()` 是独立的 Host 专用作者样例端口。它接收独立签名的审核挑战，重核当前机主和已应答设备，创建私有有界目录，同一 nonce 只运行一次，并通过该挑战的审核租约直接上传。返回的元数据须由另行登记的设备密钥签署；广州须独立读取不可变对象并核验媒体，才能签样例证据。设备密钥登记有单独固定的 WebSocket 证明与 ACK，不授予审核或接单权。上海只收到元数据。源码与模拟运行器测试不代表核验器已部署、Windows GPU 出片或 Mac 交付。

`validateNativeH3PresenceChallenge()` 每次读取实际配方与模型身份和已绑定试片，不执行渲染。读取前后都核对已鉴权机主、已应答设备及服务端签发的当前连接 UUID。独立签名的在线续验计划锁定相同源码、合同、原生绑定与既有审核样例。`observeNativeH3DevicePresence()` 只在该 ready 连接发送固定 nonce 与签名帧，最多等待十秒取得精确 ACK，与其他观察共享八项待应答上限。缺少 `connection_id` 的旧 `auth_ok` 保留普通任务兼容，但不授予在线续验权限。缓存的 ready 布尔值和 JSON 复制的凭据都不能续签设备安装证明。

<a id="model-experience"></a>

`node` 服务可通过与 Hello 相同、带进程品牌的已发布原生适配器，确认仅有 H3 的部署资格。返回资格前会重新读取当前机主、已应答 worker 与连接、catalog 身份、源码与设备证明及固定实际 provider。缺少、复制、过期或设备不匹配的证明，以及 provider 不可用或配方身份变化，都会拒绝这条原生路径。此读取不依赖默认文字运行器，不渲染 GPU 作业，也不额外授予机主权限；实际执行仍受已有持久化策略与空闲准入控制。

已移除或失效的旧文字执行器，不会否决独立核验通过的原生产物执行器。面板开关读取当前已核验的产物任务类型，不再把已购文字执行器清单为空当作完全没有执行器。经过适配器复验刷新，过期设备证明或不可用的真实 provider 会退出该集合，接单随即恢复暂停；缓存的非空清单不授予原生任务执行权。

已发布原生别名只在真实 worker 的 `auth_ok` 提供当前连接 UUID 后同步。`refreshNativeH3OrderAdapters()` 在同一连接发送最多十六项、每项精确十四字段的 V1 声明；上海依据自身已批准归档、合同、原生绑定及当前设备证明摘要，确认请求与精确任务集合，随后本机才开放该别名接单。每次刷新重新读取真实 provider 和证明；同一已核验身份避免短暂撤销接单，拒绝、源码或 provider 变化以及证明过期则撤销原生路由。普通已购适配器保留原来的重连流程。

V1 共享运行时和只含 JSON 的归档可以在不同 Windows 上复用，但一份不可变投稿仍绑定具体配置。私有绝对路径和模型身份参与 `ownerConfigDigest`，这些路径不会进入归档。第二台电脑摘要不同，必须准备并发布自己的绑定；共用 `video.render` 不允许借用另一设备的证明，也不允许暗中替换原投稿配置。

### 独立 V2 机主准备与执行

[V2 provider](src/h3-video-v2.ts)只接受 `qianshou.h3-owner.v2` 和独立生成的八字段 `qianshou.h3-self-test.v2` 回执，使用分别锁定的 `runtime/h3-v2` 入口/运行时及 `/v2/recipes/qs_new4/identity`。实际读取器返回配方、模型、首帧和私有路由配置 SHA，私有机主摘要包含这四项及现有本地机主身份。路由 YAML 字节影响私有身份，受控配方和真实模型字节测量仍为公开身份。V1 配置、试片、身份响应或任务输出都不升级。

同一作者在真实配方/模型/首帧/运行时身份一致时可以在多设备共享 V2 公开声明。每台设备仍需独立私有摘要、当前服务端修订号、已登记密钥、独立双样例核验及当前连接证明/ACK。配置改变及改回旧配置都不复用先前修订。状态按机主 schema 显示对应 provider 的真实失败，不选择曾经 ready 的另一代缓存。

artifact 消费者在调用固定 runner 前要求原始十八字段派单租约。任务执行时仍可刷新，同一元组的新证明能够完成 400 秒的夹具任务而不重跑样例。修订、私有配置、密钥或 socket 改变会拒绝旧排队任务。撤下别名会拒绝其排队原生任务，不会交给普通或模型 runner。持久 nonce 声明先于渲染写入，不确定或部分完成的结果持续保留；只有归属正确、完整完成且摘要相符的声明，在过期并经过 300 秒宽限后按显式版本清理。

实际 Loader、HMAC 桥、provider 和 HTTP 夹具测试覆盖这些边界，不代表新 Windows 适配器接口、V2 GPU 试片、生产审核或 Mac 调用 Windows 已通过；这些需要分别取得当前回执。

### Canonical H3 协议测量

Canonical 解析器与 V1/V2 provider 分开，校验实际十二字段公开身份、提交时的两个预期摘要、终态源码/类来源/模型及编码器测量、固定本机任务路径，以及有界且摘要一致的 MP4 字节。解析不登记软件、不执行任务、不声明设备就绪，也不授予发布或派单权限。调用方仍需批准的软件身份、当前私有配置与进程证据，以及真实本机自检。合成协议夹具不能证明这些设备结果。当前任务响应未公开任务描述、seed 或首帧身份；执行调用方必须绑定自己提交的输入及当前进程/配置证据，才能接纳完成结果。

Canonical 只读通道每次只直接访问本机回环地址的公开身份、Host 已绑定任务或视频固定 GET 路径。读取不跟随重定向、不携带环境凭据，完整请求受期限约束，JSON 严格解码 UTF-8，流式上限为 64 KiB JSON 或 16 MiB MP4；视频还须与终态大小和 SHA 一致。该通道尚未注册，不提交任务、不证明软件已获批准、不运行自检，也不授予派单资格。

独立的 [ComfyUI 视频运行器](src/comfy-video-runner.ts)只在 Host 提供精确的声明和依赖摘要、当前安装与资源核验、持久的单次预留后，接收一份已审核私有图。它只替换声明的文字、整数和有界 PNG/JPEG 输入，为 MP4 与辅助抽帧输出分配本次任务专属文件名，并向固定本机 ComfyUI 端口提交一次。Host 必须先持久记录 ComfyUI 签发的 prompt ID，才能轮询。对于 VHS 输出，运行器在提交前强制 `save_metadata=false`，阻止 VHS 将私有图写入视频输出元数据。运行器只接受与该历史记录对应的一份 MP4，并核验字节上限、SHA-256、文件头、时长、帧数和尺寸。POST 回包丢失时结果保持未知；它不重新提交，也不中断其他任务。仅供 Host 使用的[驻留任务桥](src/comfy-video-resident-bridge.ts)在注入的 GPU 占位内，将已启动的任务租约、已审核的私有草稿和持久提交记录绑定。桥自身拒绝任务与尝试 ID、幂等键混配，拒绝过期的任务截止时间或租约，以及小于审核合同的输出上限。Host 还须独立绑定签名任务输入与暂存媒资摘要、确切的 Comfy 端口和 ffprobe 程序，以及 GPU 占位。POST 前的回调在账本锁内花掉单次预留；仍为 `reserved` 的准备失败，只有拿到权威终态证据才能显式释放；`submitting` 或未知 POST 持续阻断。POSIX JSON 账本在 Windows 仍安全拒绝；独立的 NTFS SQLite 账本须显式建库并在启动时恢复，两者均未由生产服务提供。产品 Host 已有可选的已审核视频服务接入点，但当前仍无独立审核的安装、市场发布、签名样片、结果预签端点或计费权限。本机确定性夹具不证明 Windows GPU 真机执行。

运行器要求返回的 MP4 文件名和空输出子目录匹配本次预留的任务前缀；旧任务的历史产物会在下载前被拒绝。[跨系统驻留消费者](src/comfy-video-resident-consumer.ts)仅在产品 Host 显式注入已审核视频服务且当前认证连接收到审核 ACK 后开放；默认没有服务提供者。它要求 Host 独立核验签名订单，按订单中的 bucket/key/version/大小/SHA 精确读取首帧，并复核当前审核和安装。每个已审核视频任务都须在 GPU 占位前具备 Host 文件传输端口。该端口绑定原始已认证 Edge 租约，核验 MP4，并以一次 PUT 流式上传；不会退回内存缓冲上传，也不会重试结果不明的上传。首轮已审核 MP4 候选须为 1–64 MiB；底层传输的 2 GiB 容量不代表可接 2 GiB 视频订单。POSIX JSON 账本在 Windows 仍安全拒绝；独立的本机 SQLite 账本须显式建库与启动恢复。结果预签端点尚未部署，不能因此声称市场订单已执行或结算。

可选的[已审核视频路由](src/reviewed-comfy-video-resident-route.ts)把进程内签名任务、按版本固定的首帧读取与租约绑定的结果消费者组合起来。普通 `task-adapters.v1` 文本接单路径不变。[Ed25519 订单验签器](src/reviewed-video-signed-order.ts)只接受认证后的 `shard_assign.reviewed_video_order`，并使用预置的上海公钥验签：签名覆盖完整派单投影（包括全部参数、唯一带版本号的 GET URL 和当前租约令牌摘要）及独立的订单、商品、发布、机主、客户、合同、输出和首帧事实。验签器精确比对现有上海 `multi_file` 单 URL、`semantic`、Runtime V2 的派单格式；读取媒体时只使用签名固定的 bucket/key/VersionId/大小/SHA。签名订单的输入值还须匹配已审核图中非文件的输入槽。Edge attempt 保持原值，本机驻留 attempt 为 Edge + 1。产品插件挂载时读取可选的 `qianshouReviewedVideoHost` 服务，或从独立的 `qianshouReviewedVideoHostProvision` 服务构建该端口。[Host 装配工厂](src/reviewed-video-host-provider.ts)绑定本机 SQLite 持久账本和私有草稿读取器，拒绝缺失或未核销的旧账本，并在供给更新前复核已审核安装、发布、机主、本机 Comfy、ffprobe 和独立运行见证。注入方必须提供真实的已安装发布、进程/GPU、入网设备和广州样片读取器；配置值或买家草稿均不能代替。产品仍须取得设备和广州签名、当前上海连接的精确 ACK 才开放视频任务。任一依赖缺失时，Hello 与执行路由保持关闭。当前尚无完整生产装配或已部署的订单链。本机夹具或旧文本接单声明均不能授权视频市场订单。

产品内的 `qianshouReviewedVideoHostProvision` 现在只提供设备与平台观测。NodeContributor 强制绑定自己的任务尝试库、`computeCore.readPrivateVideoWorkflowDraft` 私有图读取器，以及经上海身份读取的 `computeCore.ownerAccountId`；注入方若夹带这三项替代值，装配会拒绝。市场目录的元数据安装不等于机主设备安装。目前仍缺从私有图/包读取的生产安装服务、已审核发布读取器、视频用途的入网设备密钥、GPU 占位与运行见证、广州签名样片服务，因此此次改动不会开启视频供给。

<a id="managed-owner-setup"></a>

机主接入使用正常认证的账户和 profile，在 Harness home 中解析独立的 V2 与 canonical 私有修订目录。每次保存完成都在共用事务中明确选择对应运行时；独立选择修订号防止 V2/canonical 切换及切回后复用旧 provider 状态。未明确设置 `h3OwnerConfigPath` 时，中文界面保存会撤下旧 provider 状态，并在当前连接上重新读取当前选中的受管配置。明确的 Host 覆盖配置保持优先，并禁用受管写入，避免界面保存后实际未生效。就绪状态跟随实际机主 schema、配置原始字节、账户、profile 和修订；迟到的异步结果不能覆盖新状态.

检查、保存和操作状态读取不执行程序或启动 GPU。用户明确开始后才运行一次五秒本机试片。保存和试片共用排他操作锁；pending 或 unknown 持续记录并阻止新接单，不自动重试。适配器输出目录是真实服务输出位置，试片工作区则由 Host 私下生成。Host 签发的不透明上下文，在异步账户读取前将试片和草稿请求绑定到已检查的机主和修订。真实本机证据允许准备草稿，平台审核、设备样例和接单授权仍分别核验。

私有持久试片守卫覆盖共用同一 `DSH_HOME` 的机主和 profile。新 Host 在读到守卫之前保持暂停；新的 provider 准备和执行、配置保存、显式试片、审核样例、产物选择和普通接单均须核对它。重启遗留的 pending 或未释放互斥锁仍按 unknown 处理。空配置、切换登录、进程退出或适配器健康都不能清除该操作，只有操作本人经核验的终态转换才能清除。检查、状态和保留操作的开始响应保留原始 ready 或 failed 证据，但同一操作仍在运行（包括提交终态）时，对外呈现不带完成时间的 pending。共同守卫确认 clear 后才显示已完成状态；守卫未确认或无效时呈现 unknown，并继续阻止准备草稿。读取或轮询不会释放锁，也不会重新试片。纯配置身份和 presence 读取保留全部身份校验，不要求空闲，使已有租约能够在暂停新接单后完成。原生供给撤下后，仅允许同一认证会话真实交付过的租约数限定、能力列表为空的暂停心跳；新派单仍被拒绝。该守卫不覆盖不同 Harness home 或系统用户；适配器的物理执行互斥仍是另一层边界。文件同步与比较交换不证明 Windows 硬件断电后的持久性。

同一正常 `DSH_HOME` 中，V2 试片事务与内部执行预留共用独占锁。预留在进入固定 Host 执行端口前同步 pending 日志；执行、核验或持久终态提交不确定时，两项记录都保留。释放前核对原打开文件、inode 与 nonce 字节；进程退出、时间经过或适配器健康均不能授权恢复。纯身份读取仍可服务已有租约结果与 presence。实际 Host 将预留接入已接订单与签名审核执行；预留本身不提供 Windows 进程见证；不同 HOME、OS 用户及 Windows 硬件断电持久性不在保证范围内。

## 模型体验

### 隔离任务输入

#### 模型看到的内容

隔离智能体运行器使用显式提供方与模型时，已准入类型进入新会话；机主为该任务明确绑定本机插件或已购运行包时除外。用户消息就是已准入的提示词，没有别的内容。助手的回复在 `word_count` 落点上放进 `result_lines` 和 `summary_text` 交回。会话没有父对话种子。setup 挂上宿主的默认智能体预设，专员因此能在宿主沙箱和审批下使用该预设的命令和文件。会话头里的 cwd 是新建的私有目录，不在机主的任务存储目录下，结束后会删除。部署提示词能解析 `{{cwd}}`，但不会向模型暴露机主工作区根目录。交付前会隐藏回复中客户未提供的本机用户目录和任务目录路径；客户在任务里明确提供的路径保持原样。没有隔离路由或已选插件时才运行本地 `word_count` 计数。被拒绝的邀请不发起模型请求。 `isolatedReasoningEffort` 只控制这个任务会话。千手出厂路由设为 `off`，与机主 CEO 对话的思考开关独立。留空则使用所选适配器的默认值；所选适配器和模型需要支持相应档位。

#### Token 影响

隔离请求只发送已准入的提示词，不附加类型标签。输入相关 token 数随这段提示词变化，此包不添加父会话历史。心跳、策略读取、确定性词数统计运行器及绑定的本机插件均不增加模型输入 token。

#### KV 缓存影响

每个隔离任务创建独立会话并向其中追加输入，不改变前台会话可复用的前缀。任务输入、提供方路由或模型选择的变化可能改变请求前缀复用；提供方的缓存可用性与淘汰不归本包控制。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- 设置了 `isolatedProvider` 和 `isolatedModel` 时，已准入类型在隔离会话里执行；明确绑定本机插件的文字任务除外。它们都不继承 CEO 默认路由。没有模型路由和插件绑定时，`word_count` 在本地运行。AT-01 两机回传仍未绑定。没有本地运行器或该路由的类型会在加载时失败。
- 本机插件接单绑定只覆盖当前宿主的现有文字任务；它不创建上海市场商品、买家权益、价格、平台安装回执或公开派单权。真实客户订单仍需端到端平台受理回执。
- 隔离智能体路由尚未与机主选中的本机服务建立经验证的绑定，常驻接单仍不可用。安装或选中某个工具不代表授权使用无关模型账户。必要活动或内存读数未知时暂停新接单。
- 私有 cwd 和结果保护可防止普通回复意外暴露机主路径；挂载的宿主预设仍保留原有工具权限。通用外部订单在具备经验证的单任务文件系统沙箱之前，不能宣称文件隔离。
- 能力盘点器和调度适配器由部署方提供可信本机事实；资源事实不可用时，接单前必须安全失败。
- 收益只是核心确认的待处理账本引用；计价、结算、退款、税务和提现仍归商业系统负责。
- 策略测试使用隔离存储和受控传输；媒体检查也使用实际临时 HTTP/SQLite 和子进程。这些验证机制，不代表生产节点或支付验收。

<a id="dev-note"></a>
### 开发备注

保持此包只做编排。需要新增线字段、持久状态或结算转换时，先扩展 `compute-core` 或计费/调度合同。

新版 canonical 读取器校验实际十字段机主测量与自摘要，并在五字段作业收据和十字段完成测量中保留同一个见证。固定媒体读取器在请求前对照已捕获的机主、作业、来源、配方、模型及编码器身份。源码 oracle 使用实际收到的 Windows 48558c 纯构造函数；其中模拟进程与字节不证明 Windows 已安装运行、GPU 出片或平台批准。本层仍只读；实际单次提交、执行预留和上传消费者另行接入。

### Canonical H3 提供方与已接任务执行

动态提供方只按精确的私有配置 schema 选择 canonical 运行时，与固定 V1、V2 runner 分开。它核对受支持的完整源码清单、公开身份、提交时机主见证及已有真实本机试片。准备与身份读取不提交 GPU 任务；公开的 canonical Node 绑定端口供实际源码创作模板使用。

正式执行要求原始已接租约对应的私有单次许可。实际 Host 将同一租约对象与当前 EXECUTING 尝试、账号、worker、已应答连接逐项核对，再进入共享执行占位。捕获的 runner 提交一次，轮询原作业，核验相同见证和有界媒体，然后使用原结果上传端口。提交结果或终态写入不确定时，持久占位保持阻断，不能自动再提交。接单忙碌只暂停新声明，纯身份核对及已接任务交付仍可继续。

签名审核执行按精确 ABI 选择 canonical 提供方。独立的私有单次许可保留原始 nonce、机主、设备、源码及已应答连接；共享占位覆盖原 runner、审核专用直传和两项终态提交。结果不确定会阻止后续审核执行。纯签名 presence 仍可读取，不生成视频或释放占位。

原生发现只跟随当前机主、设备、连接和配置 epoch 的已核验 H3 事实。空结果等待三十秒，新的应答或显式配置操作可使缓存失效；删除配置只撤回一次声明。静态产物能力不触发 H3 查询，普通已购运行时仍沿自己的发现路径。

147 项审核、presence 与回归用例使用受控 HTTP/套接字样例和真实签名挑战，不证明已安装 Windows 软件、GPU 产物、平台策略批准或市场验收。中文受管 canonical 保存与试片向导仍为单独待接入项。

### 自动算力共享

启动和状态读取会独立检测真实硬件及已有回环服务，不以开启共享或取得签名目录为前提。`mediaLocalComfyOrigin`、`mediaLocalImageOrigin` 和 `mediaLocalVideoOrigin` 默认读取本机 ComfyUI、图像及统一工作流接口；显式空值关闭对应观察。`mediaLocalProbeTimeoutMs` 限定整次本地读取。每种模式的 `local` 仅投影通用库存数量、已识别 API 状态和采用状态；读取失败表示不可用或未知，不表示模型不存在。已有 Qwen 图像适配必须同时核对固定模型项、工作流类别和实际 API 元数据；其研究服务仍需正式验证，不发布收费能力。已安装受审包先核对每个文件的大小及 SHA-256，完整包跳过下载；只有同一受信包的精确已认证实例才可直接采用而无需重启。已识别的现有 API 可直接用于零收费元数据登记和只读往返；受审运行 ABI 和独立设备资格仅用于正式收费准入。发现过程不停止、覆盖服务，也不向其提交任务。


Host 提供 `GET /api/qianshou/node/sharing/status`，以及同前缀的 `POST /enable`、`/pause`、`/resume`、`/revoke`。确认后的开启、恢复请求精确包含 `{mode, requestId, scopeId, consent: {version: 'qianshou.media-sharing-consent.v1', connection: true, execution: 'idle_only' | 'disabled'}}`；暂停、撤销精确包含 `{mode, requestId, scopeId}`。缺确认返回 `SHARING_CONSENT_REQUIRED`，账号范围变化返回 `SHARING_SCOPE_CHANGED`。Host 私有身份把权限绑定当前账号、设备及所选模式，不向界面暴露这些身份。SQLite v2 增量迁移保留旧意图及任务，不从旧 desired 记录产生权限。结果不确定的命令只以当前账号 `GET /status?request_id=UUID` 查询；已提交 UUID 不能改变含义。状态包含不透明的当前账号 `scopeId`、分模式 `authorization` 及原操作回执。退出账号持久撤销其新供给权限，重新登录不自动恢复确认。暂停保留权限但停止新准入；撤销禁用连接、执行两项权限。已接原任务及其占位继续保留。

Host 启动时及每次状态刷新都用新公开 nonce 探测默认域名，设定有限超时，不携带账号或设备凭据。响应只证明广州网关可达。设备授权来自实时广州握手；当前 epoch 的已接受心跳另行观察。持久设备 ID 和账号登录不能形成这两种证明。账号切换丢弃旧设备观察。探测失败返回有限的不可用状态，不登记供给，也不重试 GPU 任务。默认域名不提供官方模型包或设备资格。

明确的当前设备连接授权可以在官方包尚不可用时建立在线连接。此时登记空能力、空闲槽位为零；握手或心跳不构成某模式的派单资格。旧用户 OFF 模式、面板开关和 `node` 服务授权不授予或阻断这一独立连接，也不会被修改。仅闲时执行还须单独确认执行权限，取得当前受审包及设备资格，并在已有用户资源限额和部署并发上限内实测空闲、语音、前台活动及可用内存。未知观察拒绝准入；部署 OFF 禁止执行，仍保留已明确授权的零槽在线状态。原提交权被消耗前再次读取活动。协调器仅拥有自己启动的精确通道，跟踪自动重连 epoch；现有手动通道不归它所有。暂停、撤销后，已接原任务保留零槽会话、固定状态及结果操作和原运行时绑定。账号切换撤销新供给权限，保留未完成占位及已接任务的受管进程，不以其他账号操作它们。未知任务不重启、不重派。

共享暂停或执行禁用时冷重启 Host，已经提交的 running/unknown 原任务仅在存储的官方签名按钉住公钥、账号/设备/worker 及精确计划档位复核通过、全部已安装文件大小和 SHA 匹配、私有现存进程及凭据通过精确实例健康检查时，恢复原运行时 GET 绑定。已存回执的到期窗口不产生新安装或准入权限。只恢复采用不会下载、启动、提交或关闭这一进程，不发布恢复所得能力，也不构成新接单资格。原实例不存在、凭据或 worker 身份缺失、文件改变时，原任务保留 unknown 和占位。已生成、上传中或待结算记录继续按固定原文件及结果状态恢复，无须新运行时或重新取得资格。

运维配置 `mediaGatewayOrigin`、`mediaMetadataPublicKey`/`mediaMetadataKeyId`、`mediaGuangzhouPublicKey`/`mediaGuangzhouKeyId`、`mediaUploadPublicKey`/`mediaUploadKeyId`、`mediaAuthorizationPublicKey`/`mediaAuthorizationKeyId`、`mediaOrderPublicKey`/`mediaOrderKeyId`。它们分别钉住仅元数据用途的安装/资格回执、正式结果验真、上传票据、上海授权和当前订单的独立公钥。元数据配置默认空，绝不回退到结果公钥；元数据签名者不能认证可计费结果，原安装回执恢复也仅使用元数据公钥。只配置元数据不能开启正式准入；独立结果、上传和租约公钥仍为必要条件。`mediaDownloadOrigins` 限制模型包下载来源，默认空列表仅允许配置的广州来源。公钥由部署配置提供，不从界面输入。正式安装必须有上海已确认的现有 worker UUID；它不创建账号、worker 或正式资格。零收费 API 发现及内置私有 wrapper 不要求这个 worker 绑定。

`sharing-coordinator.ts` 请求 challenge 绑定的官方安装清单，并实测操作系统、GPU 和内存。`sharing-runtime.ts` 按不可变 ETag/Range 断点下载平铺文件，逐个校验完整 SHA-256，安装到账号私有目录，只启动受审入口。子进程使用清理后的环境、私有运行时 Bearer 文件、loopback 地址和随机实例；健康检查必须匹配受审包、执行器及档位身份。监督器只接管同一已认证实例，确认实际退出后才能替换，不按磁盘记录中的 PID 杀其他进程。缺发行、许可或人工评审材料显示 `catalog_unavailable`，缺独立设备验证显示 `verification_pending`。本机发现、私人研究 Qwen 和旧 H3 试用不构成收费资格。

取得当前账号、设备及模式的连接确认后，Host 仅向 `POST /v1/nodes/api-observations` 报告去敏标识。已识别 Qwen 图像 API 提供实际模型、工作流 ID，未知哈希保留 null；不可读或未适配的本机视频不借用远端电脑 API。这条元数据路径不需要目录、元数据签名者、RTX 回执、worker 绑定、新下载或 GPU 任务，设备仍发布空正式能力及零空闲槽。原出站通道附带独立可选 `apiProbes`，时限为 90 秒；每次只请求固定本机健康、模型、工作流 GET，在 POST 前把原 UUID/epoch 响应写入增量私有 SQLite 元数据 outbox，重复挑战保留同一正文。稳定观察快照保留 revision 和时间；仅未确认且超过 60 秒的元数据重新观察并轮换，已确认快照不频繁改版。分模式 `api` 仅返回安全友好名称和当前登记、往返状态，不含本机地址或凭据。广州确认有效 120 秒，60 秒后用新只读挑战续期；账号、epoch、授权或 API 改变会清除当前确认。这些回执证明 API 接通，不证明生成、正式资格、收费或收益。

明确的图像连接与闲时执行许可还可以按真实 Comfy 模型和类别元数据创建内置私有固定 Qwen 任务 API。它复用已有模型，不下载，不启动或替换 Comfy，也不停止现有 Qwen 服务。已就绪的旧 Qwen API 保持运行，私有 wrapper 仅补持久原任务处理；不可读 API 只有匹配相同固定配方时才可适配，认证拒绝或不支持的元数据不会被绕过。wrapper 使用实际 `comfy-pilot-image-154f7d6133fe0276` 工作流 SHA、固定 2048×1152 输出和八步执行；模型 SHA 未独立测量时保持未知。运维 `mediaPilotTimeoutMs` 与 `mediaPilotMaximumResultBytes` 限制请求和 PNG 读取。账号/设备私有身份及 SQLite 保留原未知作业，新提交前重新测量当前闲时权限。暂停、撤销、退出账号与 Host 关闭只停止这个自有 API，不影响上游 Comfy 及其原工作。元数据 GET 和连接确认不提交 GPU 任务，也不授予收费资格。

本机模型库存与 API 可用性是独立观察。连接拒绝、超时或 HTTP 失败表示服务不可用，不丢弃已经发现的模型文件。认证拒绝单独显示；不受支持表示成功读取的元数据未匹配适配合同，不表示已经发现视频服务或视频模型。

`mediaResearchEnabled` 默认 false。显式配置的千手部署仅按当前账号图像授权和固定八步 Qwen 工作流消费广州独立研究收件箱。`mediaResearchWaitMs` 默认 0（0–25000），`mediaResearchMaximumRecords` 默认 256（1–4096），`mediaResearchExecutionIntervalMs` 默认 5000（1000–5000）。资源报告绑定广州已确认的当前观察 revision 与 epoch；空闲或安全事实未知时保留 null。广州负责权威单槽预占，正式能力和空闲槽位保持不变。新 GPU 提交还须重核实际本机空闲、语音/内存策略、Comfy 队列、原租约及正式/试用/更新共享准入。不能消费其他账号的租约。

[研究消费者](src/research-consumer.ts) 在每次不可逆发送前同步保存原领取、提交和上传权。领取 ACK 丢失不授予 GPU 提交。运行时仅收到一次原 attempt UUID，并保存实际返回的 backend ID。未知生成仅通过原 GET 恢复；缺原运行时身份时保留未知。已暂停、撤销或冷启动的原任务可使用既有私有身份，不启动 API 监听、不下载模型、不再次提交。PNG 上传 ACK 丢失仅查询原任务状态，即使完成任务已退出收件箱也可恢复。广州独立核验完整 PNG，只有广州可声明完成。已提交未决任务阻断共享桌面更新 registry；仅排队租约不占 GPU 忙态。这条路径不拥有价格、收费档位、结算或收益权限。CPU HTTP/SQLite 与 Loader 夹具不证明生产 GPU 或 Windows 验收。

可选设备元数据按已认证当前 epoch 报告既有实测操作系统/架构、CPU、GPU、内存和独立显存；不可用事实保持 null，不发送主机名、私有路径、地址或凭据。广州通过可信账号核验器解析账号名称。缺这些可选路由的旧网关仍可连接。研究轮询、资源上报和设备元数据独立于状态/确认队列；读取不可用不表示本机模型缺失。

状态在后台硬件、模型或广州读取完成前先返回当前账号的已知快照，不等待生成或受管运行时健康请求。`mediaStatusTimeoutMs` 默认 1000（100–10000），限定身份/日志就绪等待；新账号尚未就绪时不显示继承权限或旧观察。受管运行时健康单独刷新，过期就绪状态会撤回。客户端随后轮询新测事实，无须排在不可用服务之后持续等待。

新的明确授权启用/恢复操作会重新读取实际硬件、本机 API 元数据和广州公开探测，即使当前设备已拥有闲时授权。只有原账号、scope 和操作仍为当前意图时才继续准备；重复已提交 UUID 不重复准备。配置本机发现时，已有 API 连接和元数据不请求收费安装清单，也不等待正式资格或 GPU 空闲。缺失、拒绝认证或不支持的视频 API 保留实际 `api.status` 并返回 `runtime_unavailable`；观察未知时保持检测中。既有已安装正式运行时仍保留独立资格及执行门，免费接通不会被写成收费 `sharing`。

受审包实现 `qianshou.media-runtime.v1`：已认证 `/health`、`/shutdown`、一次 `POST /v1/media/jobs`，以及只恢复原任务的 `GET /v1/media/jobs/{attemptId}`。启动参数包含 `127.0.0.1`、`{PORT}`、`{AUTH_TOKEN_FILE}`、`{INSTANCE_ID}`，可含 `{ROOT}`。Host 生成并提供 `QIANSHOU_MEDIA_BUNDLE_ID`、`QIANSHOU_MEDIA_EXECUTOR_SHA256`、`QIANSHOU_MEDIA_PROFILES` 身份元数据。提交冻结设备、买家、计划哈希和租约到期时间；运行时必须执行这一到期限制，跨重启持久保存原任务，并返回精确 task/attempt/lease/asset 及固定本机输出声明。已有试用接口须由另行受审并实现此 ABI 的发行包接入，才能承接正式任务。

`sharing-store.ts` 保存有版本的 SQLite 日志、账号操作、不可变 attempt 和事件 outbox。全局单槽约束覆盖两种模式和账号切换。首次运行时提交和结果 PUT 在发送前由 SQLite 原子认领；未知结果只能查询原任务或结果，不能取得第二次写入权。Provider 同时核验上海冻结授权与新鲜的完整输入签名，仅按广州精确输入票据读取附件，上传一个原结果，匹配独立结果回执和已提交结算回执后才能释放槽位。旧本机 GPU 准入也读取这一持久占用。上海只接收元数据，媒体字节在 Host 与广州之间传输。
