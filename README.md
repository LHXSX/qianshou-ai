# 千手 AI · 源码开放计划

大家好，我叫胖墩，来自沈阳，是一名普通创业者。过去约 500 天，我一直在尝试把分布式边缘算力和 AI 智能体做成普通人也能使用、也能贡献算力的产品。受个人精力和财力所限，我已经无法独自把它推进到原先设想的规模。因此，我决定整理并开放千手项目的源码，包括我自研的上海 V8 算力引擎，让做过的工作能够被看见、检验和继续改进。上海 V8 处于专利申请阶段，仅按非商业条款提供源码；商业使用需要另行获得我的书面授权。

千手的目标是：用户在一款 PC 客户端里提出任务；另一位机主在明确授权后，可以用自己电脑上的能力执行合适的任务，并获得可核对的收益。使用者和算力贡献者是**同一款客户端中的两种角色**，不是两套彼此割裂的软件。长期愿景是全球共享算力；目前的代码和运行证据距离这一愿景还有明显距离。

## 项目由什么组成

- **上海 V8：自研控制引擎。**负责账号与任务定义、切片、节点资格筛选、调度、派发、租约与故障恢复、结果验真及账本结算。普通任务可以通过节点连接执行。正式图像／视频方案中，上海负责控制元数据、调度与计费，不承担媒体文件交换。
- **广州：节点 API 与媒体交换。**负责接收节点连接和能力报告、管理本地 API、图像／视频媒体交换及运营管理。广州已有部分接口和试用链路；正式媒体通道仍须按实际部署与跨设备回执逐项验收。
- **千手 PC：智能体与算力贡献入口。**同一客户端承载对话、技能和机主授权的算力分享。当前 PC 产品建立在 DeepSeek Harness（DSH）框架之上；我们会保留其上游版权声明和许可，把上游框架与千手新增实现清楚区分。
- **历史客户端与配套站点。**第三代“千手节点”的 Rust／Tauri 源码目前保留在[独立历史仓库](https://github.com/LHXSX/qianshou-node-client)，**未复制到本仓库**；该旧仓尚无明确的仓库级再利用许可证，公开可读不等于已授权复用。当前千手 AI 是第四代产品方向。第一、二代的完整独立源码还在查找与归档，不能用后来的源码代替它们。本仓库也整理官网、管理台和相关开发文档；每个目录的来源以发布清单为准。

普通任务的主链路是“提交任务 → 上海定义和切片 → 匹配已授权节点 → 派发 → 验证结果 → 结算”。图像／视频的目标链路是“PC 用户端 → 上海控制面 → 广州媒体通道 → PC 贡献端 → 广州媒体通道 → PC 用户端”。这两条链路的验收进度不同，请勿把试用出图或试用视频当作正式收费媒体服务。

## 已经做出的成果

截至 **2026 年 9 月 30 日** 的只读核查，上海现网 V8 后端正在运行，健康检查中的数据库和 Redis 状态正常。它使用 Python、FastAPI、PostgreSQL、Redis 等组件；核心源码包含 Workload／Shard 状态机、三种调度模式（主动派发、节点拉取、会话）、跨进程网关、送达确认、失败回收、结果验证和事务内的分润／退款逻辑。现网静态注册表有 **74 种任务定义**，并实现了 **12 种切片器、12 种聚合器**；这些是源码能力清单，**不是 74 种任务均已实机跑通**。动态技能注册另有独立条件。

历史回执中，上海曾完成一笔普通跨设备任务并写入机主奖励；Mac 客户端曾完成固定试用出图，以及“文字 → 首帧 → 五秒视频 → 播放／下载／重启恢复”的试验链路。PC、广州管理台、设备登记和 API 探测也有各自的源码与有限回执。我们会在文档里保留这些证据的日期和范围，不把源码存在、测试通过、服务上线和商业闭环混成一句“全部完成”。

## 仍未完成与已知问题

- Windows 设备上的原生出图／出视频、真实 MP4 回传与重启恢复，还需要独立的实机端到端验收；其他用户下载后自动发现任意模型、生成适配 API 并稳定接入广州，也不能仅凭现有候选代码宣称完成。
- 正式图像／视频的设备资格、广州交换、上海调度、四档报价、真实收费和唯一结算，尚未形成完整生产回执。跨多个真实 PC 的容量、公平性和故障恢复也未做足够的公开可复现实验。
- 第四代客户端的签名安装包、可验证的自动更新 feed 与跨平台安装体验仍待交付；技能市场、投稿和发布链路需要继续梳理权限与上架流程。
- `website/` 保留历史下载清单供溯源；清单中的所有旧安装包均标记为不可下载，未按第四代客户端标准重新验收。旧版一键安装脚本因解析和安装校验缺陷已从候选仓移除。当前第四代客户端的安装状态只以独立的千手 PC 下载页和经核验的发布清单为准。
- 上海现网源码与此前云效快照并不完全一致。开源包应以经过冻结、脱敏和可重建验证的版本为准。现网审查还发现调度公平性注释与实际 NCE 主排序不完全一致、心跳可能续租已停止运行的分片，以及聚合器重复定义软失败检测函数；这些需要代码修复和回归测试，不能在说明里略过。

## 当前源码验证范围

在 macOS arm64、Node 22.23.1、pnpm 11.7.0 上，从本仓库候选源码安装依赖后，`pc/` 的 `pnpm run qianshou:build` 已通过；PC 与广州研究链路的定向测试为 9/9 通过。`website/` 的 `npm run build:check` 已通过。广州的定向测试通过，但全仓构建仍有未解决的生成类型与管理台测试接口错误，范围与复现命令见 [`guangzhou/TESTING.md`](guangzhou/TESTING.md)。上海 V8 的 P0 离线安全测试 75 项通过，但完整测试仍有失败，详见 [`shanghai-v8/TESTING.md`](shanghai-v8/TESTING.md)。以上均不是 Windows 原生安装、现网应用部署或正式收费链路的验收。
